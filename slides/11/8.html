SPF + DKIM + DMARC

SPF (RFC 7208) — DNS TXT, які IP можуть слати від домену.
v=spf1 ip4:192.0.2.0/24 include:_spf.google.com -all
DKIM (RFC 6376) — криптографічний підпис у заголовку (мінімум RSA-2048). Ротація — раз на 6 міс.
DMARC (RFC 7489) — поверх SPF+DKIM. Політика: p=none / quarantine / reject.
v=DMARC1; p=reject; rua=mailto:dmarc@ex.com; adkim=s; aspf=s
Gmail + Yahoo мандат (02.2024): для 5000+ листів/добу — обов'язкові SPF, DKIM і DMARC. Покриття DMARC топ-1M доменів зросло з ~40% до ~67% за рік.

Чому SMS/TOTP/Push обходяться

  • 10K+ організацій постраждали (MS 2023)

FIDO2 / WebAuthn

  • Прив'язка до origin
  • Приватний ключ у TPM/Secure Enclave
  • YubiKey 5 ($50), Feitian ($25)
  • Passkeys 2024: 800M+ акаунтів Google
CISA Phishing-Resistant MFA Guide: 1) FIDO2/PIV — обов'язково для high-value · 2) App + number matching · 3) SMS/voice — last resort.

SLAM Method + helpdesk після MGM

SLAM (HIPAA Journal)

  • Sender — повна email-адреса
  • Links — навести курсор
  • Attachments — підозра
  • Message — граматика, тон, тиск

Helpdesk-протоколи

  • Multi-factor identity (ID + manager + ticket)
  • Callback на номер з HR-системи
  • Video verification для passkey reset
  • Manager approval для MFA-resets
  • Logging усіх identity-перевірок

Ключовий висновок

Захист працює лише як комбінація трьох шарів

DMARC + FIDO2 + EDR (технічне) + helpdesk-протоколи (організаційне) + awareness-тренінг (людське) = PPP падає з 34% до 4–5%

Жоден з шарів окремо не працює.
