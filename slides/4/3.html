Кафедра ТЕІБ, Ужгородський національний університет

SYN та Connect скани

SYN Scan (-sS)

  • "Напіввідкритий" / stealth scan
  • Flow: SYN → SYN-ACK → RST (не завершує рукостискання)
  • Open: отримує SYN-ACK
  • Closed: отримує RST
  • Потребує root/admin
  • Швидкий, менш помітний
  • Дефолтний скан для root

Connect Scan (-sT)

  • Повне TCP-рукостискання через connect()
  • Open: SYN → SYN-ACK → ACK
  • Closed: SYN → RST
  • НЕ потребує root
  • Повільніший, повністю логується
  • Єдиний варіант без привілеїв

Спеціальні типи сканів

FIN Scan (-sF)

Лише прапорець FIN

  • Closed: RST
  • Open: тиша
  • Не працює на Windows!

Xmas Scan (-sX)

FIN+PSH+URG ("різдвяна ялинка")

  • Та ж логіка що FIN
  • Незвична комбінація обходить прості фільтри

Null Scan (-sN)

Жодного прапорця

  • Та ж RFC 793 логіка
  • Мінімальний пакет

ACK Scan (-sA)

Лише ACK

  • НЕ визначає open/closed!
  • Маппінг правил фаєрвола
  • Unfiltered: RST отримано
  • Filtered: тиша
Увага: FIN/Xmas/Null працюють лише проти RFC 793-сумісних систем. Windows, Cisco, BSDI відправляють RST незалежно від стану порту.

Idle (Zombie) Scan

Крок 1

Probe zombie → отримати поточний IP ID
(наприклад, 31337)

→
Крок 2

Надіслати SYN до цілі зі spoofed IP = zombie

  • Порт відкритий: ціль → SYN-ACK → zombie → RST (IP ID +1)
  • Порт закритий: ціль → RST → zombie ігнорує
→
Крок 3

Probe zombie знову → якщо IP ID збільшився на 2 = порт відкритий, на 1 = закритий

Найстелсовіший тип сканування — жоден пакет від вашої реальної IP не досягає цілі!

nmap -sI zombie.example.com target.com

Стани портів — підсумкова таблиця

Можливі стани портів

Стан Значення
open Додаток приймає з'єднання
closed Доступний, але немає додатку. RST у відповідь
filtered Фаєрвол блокує — неможливо визначити
unfiltered Доступний (відповідає на ACK), але open/closed невідомо
open|filtered Немає відповіді — невідомо open чи filtered
closed|filtered Тільки з idle scan
