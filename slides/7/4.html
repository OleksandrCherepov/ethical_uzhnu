A02: Криптографічні збої

Тема 7.4 — Безпека веб-додатків: OWASP Top 10

Кафедра ТЕІБ, Ужгородський національний університет

Що таке криптографічні збої?

Раніше "Sensitive Data Exposure" (2017 A03). Перейменовано для фокусу на кореневій причині — неправильному або відсутньому використанні криптографії.

Типові проблеми

  • Передача даних без шифрування (HTTP замість HTTPS)
  • Використання застарілих алгоритмів (MD5, SHA-1, DES, RC4)
  • Хардкоджені паролі/ключі у коді
  • Відсутній HSTS (HTTP Strict Transport Security)
  • Слабка ентропія генераторів випадкових чисел
  • Зберігання паролів у відкритому тексті

Які дані захищати?

  • Паролі → bcrypt/Argon2 (ніколи plaintext!)
  • Кредитні картки → PCI DSS вимоги
  • Персональні дані (PII) → GDPR
  • Медичні записи → HIPAA
  • API ключі, токени → vault/secrets manager
  • Сесійні cookies → HttpOnly, Secure, SameSite

Слабкі алгоритми та атаки

Алгоритм Статус Проблема
MD5 Зламаний Колізії за секунди
SHA-1 Зламаний Колізія SHAttered (2017, Google)
DES Зламаний 56-біт ключ, брутфорс за годину
RC4 Зламаний Bias у keystream
3DES Застарілий Повільний, 64-біт блок
AES-128/256 Безпечний Стандарт шифрування
ChaCha20-Poly1305 Безпечний TLS 1.3
SHA-256/384/512 Безпечний Для цілісності даних
Heartbleed (CVE-2014-0160) — витік 64KB пам'яті OpenSSL за кожен запит. Скомпрометовані приватні ключі, паролі, сесії. 17% всіх HTTPS серверів були вразливі.

TLS/HTTPS та безпека транспорту

TLS 1.3 (2018)

  • Видалені слабкі шифри (RC4, DES, MD5)
  • 1-RTT handshake (замість 2-RTT)
  • 0-RTT resumption
  • Perfect Forward Secrecy обов'язковий
  • AEAD шифри: AES-GCM, ChaCha20
# Перевірка TLS конфігурації
nmap --script ssl-enum-ciphers \
  -p 443 target

# Або через testssl.sh
testssl.sh https://target.com

# SSLyze
sslyze --regular target.com

Заголовки безпеки

# HSTS — примусовий HTTPS
Strict-Transport-Security:
  max-age=31536000;
  includeSubDomains; preload

# Cookie безпека
Set-Cookie: session=abc;
  Secure; HttpOnly;
  SameSite=Strict
  • HSTS Preload — включення домену в список браузера (hstspreload.org)
  • Без HSTS: атака SSL Stripping (sslstrip)

Захист: чеклист криптографії

Транспорт

  • TLS 1.2+ (краще 1.3)
  • HSTS з preload
  • Certificate pinning (mobile)
  • Redirect HTTP→HTTPS
  • Перевірити: sslyze, testssl.sh

Зберігання

  • Паролі: bcrypt(12+)/Argon2id
  • Дані: AES-256-GCM
  • Ключі: HSM або vault (не в коді!)
  • Sensitive data: шифрувати at rest
  • Видаляти дані, коли не потрібні

Практика

  • Не створювати власну криптографію!
  • Використовувати перевірені бібліотеки
  • Ротація ключів
  • OWASP Cryptographic Storage Cheat Sheet
  • PCI DSS для платіжних даних
Золоте правило: Ніколи не винаходити власну криптографію. Використовувати сучасні стандарти (TLS 1.3, AES-256, bcrypt/Argon2) і перевірені бібліотеки (OpenSSL, libsodium, NaCl).
