A04: Insecure Design — нова категорія 2021

Insecure Design — НОВА категорія у 2021. Фокус на помилках архітектури та дизайну, які не можна виправити ідеальною реалізацією.

Проблеми дизайну

  • Відсутнє threat modeling
  • Бізнес-логіка без abuse cases
  • Немає rate limiting на критичних функціях
  • Відсутній принцип defense in depth
  • Надмірна довіра до клієнтських перевірок
  • Незахищені recovery flows (скидання пароля)

Приклад: необмежений password reset → account takeover

Secure Design

  • Threat Modeling: STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, DoS, Elevation of Privilege)
  • Abuse Cases: "Що, якщо користувач зробить X?"
  • Defense in Depth: кілька рівнів захисту
  • Secure by Default: безпечні налаштування за замовчуванням
  • Fail Secure: при помилці → заборонити доступ
  • Least Privilege: мінімальні права

A05: Security Misconfiguration

90% додатків тестувалися на misconfiguration. Включає колишню A04 (XXE) з 2017 року.

Типові помилки

  • Дефолтні паролі (admin/admin, root/toor)
  • Debug mode у production
  • Directory listing увімкнений
  • Sample/test додатки не видалені
  • Stack traces у помилках
  • Зайві HTTP методи (PUT, DELETE)
  • Не оновлене ПЗ

XXE (XML External Entity)

<!-- Зловмисний XML -->
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM
    "file:///etc/passwd">
]>
<user>&xxe;</user>

Читання файлів сервера, SSRF, DoS (billion laughs)

Security Headers та помилки конфігурації

Правильні HTTP заголовки — простий, але ефективний захист. 80% сайтів не мають повного набору заголовків безпеки. 
# Повний набір заголовків безпеки
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), camera=(), microphone=()
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
X-XSS-Protection: 0    # Вимкнути (CSP краще)

Що перевіряти

  • securityheaders.com — швидкий аудит
  • Mozilla Observatory — комплексний скан
  • Nikto — сканер misconfiguration
# Перевірка headers
curl -I https://target.com

# Nikto scan
nikto -h https://target.com

Cloud Misconfiguration

  • AWS S3 buckets з публічним доступом
  • Azure Blob Storage без автентифікації
  • GCP Cloud Storage: allUsers
# Пошук відкритих S3 buckets
aws s3 ls s3://company-backup \
  --no-sign-request

# Інструменти: S3Scanner, CloudSploit

Захист від misconfiguration

Чеклист захисту

  • Видалити/змінити дефолтні облікові дані
  • Вимкнути debug mode у production
  • Вимкнути directory listing
  • Налаштувати security headers
  • Видалити sample/test додатки
  • Мінімалізувати error messages
  • Сегментація мережі (додаток ↔ БД)
  • Регулярне оновлення та патчинг
  • Infrastructure as Code (Terraform, Ansible)
  • Автоматичне сканування (nuclei, ScoutSuite)

Hardening Guides

  • CIS Benchmarks — стандарти конфігурації
  • OWASP Security Headers Project
  • NIST Configuration Checklists
  • DevSecOps: інтеграція безпеки у CI/CD
# Nuclei — автоматичний скан
nuclei -u https://target.com \
  -t misconfiguration/

# ScoutSuite — аудит хмари
scout --provider aws
