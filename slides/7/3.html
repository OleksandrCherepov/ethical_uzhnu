A01: Порушення контролю доступу

Тема 7.3 — Безпека веб-додатків: OWASP Top 10

Кафедра ТЕІБ, Ужгородський національний університет

Broken Access Control — вразливість №1

94% усіх веб-додатків мають певну форму порушення контролю доступу. Це найпоширеніша вразливість OWASP Top 10 2021.

Що це?

Контроль доступу визначає, що користувач МОЖЕ робити. Порушення = користувач виходить за межі дозволених дій.

  • 34 CWE у цій категорії
  • CWE-200: Exposure of Sensitive Information
  • CWE-284: Improper Access Control
  • CWE-285: Improper Authorization
  • CWE-639: Insecure Direct Object Reference (IDOR)

Типи порушень

  • IDOR (Insecure Direct Object Reference)
  • Вертикальна ескалація привілеїв (user→admin)
  • Горизонтальна ескалація (user→інший user)
  • Path traversal (../../etc/passwd)
  • CORS misconfiguration
  • Forced browsing (/admin без перевірки)
  • JWT/token manipulation

IDOR — Insecure Direct Object Reference

IDOR — коли додаток використовує ID об'єкта напряму у запиті без перевірки прав. Змінивши ID, можна отримати чужі дані.
# Оригінальний запит (ваш профіль) GET /api/users/1001/profile HTTP/1.1 Cookie: session=user_token # Атака: зміна ID (чужий профіль!) GET /api/users/1002/profile HTTP/1.1 Cookie: session=user_token # IDOR у POST (зміна чужого пароля) POST /api/users/1002/change-password HTTP/1.1 {"new_password": "hacked123"}

Де шукати IDOR

  • URL параметри (?id=, ?user_id=)
  • API endpoints (/users/ID)
  • Приховані поля форм
  • JSON body
  • File download (/files/ID.pdf)

Захист від IDOR

  • Перевірка прав на бекенді (не лише фронтенді!)
  • UUID замість числових ID
  • Непрямі посилання (mapping)
  • Авторизація на рівні об'єкта

Privilege Escalation та Path Traversal

Ескалація привілеїв

Вертикальна: звичайний user → адміністратор

# Зміна ролі через параметр POST /api/profile HTTP/1.1 {"name":"Hacker", "role":"admin"} # Прихований адмін-ендпоінт GET /admin/dashboard HTTP/1.1 Cookie: session=regular_user # JWT маніпуляція # Змінити payload: # {"role":"user"} → {"role":"admin"}

Path Traversal

Вихід за межі дозволеної директорії

# Читання системних файлів GET /download?file=../../../etc/passwd GET /image?path=....//....//etc/shadow # Windows GET /file?name=..\..\windows\system32\config\SAM # Null byte (старі системи) GET /page?file=../../etc/passwd%00.jpg
Path traversal = читання БУДЬ-ЯКИХ файлів на сервері: конфігурації, ключі, бази даних.

CORS misconfiguration та захист

CORS помилки

# Небезпечна конфігурація Access-Control-Allow-Origin: * Access-Control-Allow-Credentials: true # Відображення Origin без валідації Origin: https://evil.com → Access-Control-Allow-Origin: https://evil.com

Дозволяє зловмисному сайту читати дані від імені жертви

Захист від Broken Access Control

  • Deny by default — заборонити все, дозволити явно
  • Перевірка прав на КОЖНОМУ запиті (серверна сторона)
  • Disable directory listing
  • Log access control failures + alert
  • Rate limiting API
  • Інвалідація JWT/sessions після logout
  • Тестування: Burp Autorize plugin
