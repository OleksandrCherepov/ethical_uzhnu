Хеш-функції: від MD5 до Argon2

Хеш-функція — одностороннє перетворення пароля фіксованої довжини. Головна вимога: повільність для атакуючого.

Алгоритм Довжина Швидкість (RTX 4090) Статус
MD5 128 біт 164 млрд/сек Зламаний
SHA-1 160 біт 24 млрд/сек Зламаний
SHA-256 256 біт 22 млрд/сек Швидкий
SHA-512 512 біт 1.5 млрд/сек Для файлів
bcrypt 184 біт 184 тис/сек Рекомендований
Argon2id Конфіг. ~1000/сек Найкращий

MD5 та SHA-1 НЕ підходять для паролів. Використовуйте bcrypt (cost ≥ 12) або Argon2id.

Linux: /etc/shadow

Формат: username:$id$salt$hash:... де $id$ визначає алгоритм

Приклад запису /etc/shadow
root:$6$rounds=5000$saltsalt$hashvalue...:19000:0:99999:7:::
Префікс Алгоритм Безпека
$1$ MD5 Застарілий
$5$ SHA-256 Прийнятний
$6$ SHA-512 За замовчуванням
$2b$ bcrypt Рекомендований
$y$ yescrypt Найновіший (Debian 11+)
Команди для роботи
# Отримання хешів (потрібен root)
sudo cat /etc/shadow

# Зміна алгоритму хешування
sudo nano /etc/login.defs    # ENCRYPT_METHOD SHA512

# Unshadow для John
unshadow /etc/passwd /etc/shadow > hashes.txt

Windows: SAM та NTDS.dit

SAM (Security Account Manager)

  • Локальні акаунти Windows
  • Шлях: C:\Windows\System32\config\SAM
  • Заблокований під час роботи ОС
  • LM хеш (вимкнений з Vista) + NTLM хеш
Дамп SAM
# Дамп через Mimikatz
mimikatz# sekurlsa::logonpasswords

# Або через reg save
reg save HKLM\SAM sam.bak
reg save HKLM\SYSTEM system.bak

# Impacket secretsdump
secretsdump.py -sam sam.bak -system system.bak LOCAL

NTDS.dit (Active Directory)

  • Всі акаунти домену
  • Шлях: C:\Windows\NTDS\ntds.dit
  • Містить NTLM хеші всіх користувачів
  • DCSync атака — не потрібен фізичний доступ
Дамп NTDS
# DCSync через Mimikatz
mimikatz# lsadump::dcsync /user:admin

# Impacket secretsdump
secretsdump.py domain/user:pass@DC_IP

# Формат NTLM хеша
Administrator:500:aad3b435...:31d6cfe0d...:::

Солі, Key Stretching та сучасні підходи

Сіль (Salt)

Випадкові дані, додані до пароля перед хешуванням. Однаковий пароль → різні хеші. Перемагає rainbow tables. Має бути унікальною для кожного користувача.

Key Stretching

Багаторазове хешування (ітерації). bcrypt: cost factor (2^cost ітерацій). PBKDF2: configurable iterations (600,000+ рекомендовано). Збільшує час крекінгу в рази.

Argon2id (переможець PHC 2015)

Налаштовує: час, пам'ять, паралелізм. Memory-hard: GPU/ASIC не дають переваги. Argon2id = гібрид (data-dependent + independent). Рекомендація: 64MB RAM, 3 ітерації.

Принцип: зробити перевірку одного пароля швидкою (50мс), але перебір мільйонів — практично неможливим.
