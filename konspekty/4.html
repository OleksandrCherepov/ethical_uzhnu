Сканування мережі та Enumeration

2 год Нова

4.1 Від розвідки до сканування: місце у методології пентесту

У попередній лекції ми розглянули пасивну розвідку (OSINT) — збір інформації без прямого контакту з ціллю. Тепер ми переходимо до принципово іншого етапу: активного сканування. Це момент, коли пентестер вперше безпосередньо взаємодіє з цільовими системами, надсилаючи їм пакети та аналізуючи відповіді.

Згідно зі стандартом PTES (Penetration Testing Execution Standard), сканування мережі відноситься до четвертої фази — Vulnerability Analysis (Аналіз вразливостей). Ця фаза є мостом між збором розвідданих та їх експлуатацією.

Фази PTES

  1. Pre-engagement Interactions — домовленості та scope
  2. Intelligence Gathering — пасивна розвідка (Лекція 3)
  3. Threat Modeling — моделювання загроз
  4. Vulnerability Analysis — сканування та enumeration (ця лекція)
  5. Exploitation — експлуатація вразливостей
  6. Post-Exploitation — дії після отримання доступу
  7. Reporting — звітування

Три етапи активного сканування

Активне сканування складається з трьох послідовних етапів, кожен з яких звужує фокус:

Етап Мета Що отримуємо Приклад
1. Host Discovery Знайти живі хости в мережі Список активних IP-адрес nmap -sn 192.168.1.0/24
2. Port Scanning Знайти відкриті порти на кожному хості Список відкритих портів та сервісів nmap -sS -p- target
3. Enumeration Отримати детальну інформацію про сервіси Версії, користувачі, ресурси, конфігурації enum4linux -a target

Правові аспекти сканування

На відміну від пасивної розвідки, активне сканування залишає сліди у логах цільових систем та може бути зафіксоване IDS/IPS. Тому:

  • Обов'язковий письмовий дозвіл — сканування без авторизації може порушувати закони (Computer Fraud and Abuse Act у США, Будапештська конвенція в ЄС, Кримінальний кодекс України ст. 361)
  • Scope — чітко визначені IP-діапазони, порти та методи
  • Rate limiting — обмеження швидкості для уникнення DoS-ефекту
  • Документування — фіксація всіх дій із часовими мітками

4.2 Основи TCP/IP для сканування

Щоб зрозуміти, як працює сканування портів, необхідно знати базові механізми протоколів TCP, UDP та ICMP. Саме особливості цих протоколів експлуатуються різними типами сканування.

TCP трьохстороннє рукостискання (Three-Way Handshake)

Протокол TCP (Transmission Control Protocol, RFC 793) встановлює надійне з'єднання через три кроки:

  1. SYN — клієнт надсилає сегмент із прапорцем SYN та випадковим Initial Sequence Number (ISN), наприклад SEQ=1000
  2. SYN-ACK — сервер відповідає прапорцями SYN+ACK, власним ISN (SEQ=5000) та підтвердженням (ACK=1001)
  3. ACK — клієнт надсилає ACK (ACK=5001), завершуючи з'єднання

Експлуатація у скануванні:

  • TCP Connect scan (-sT) — завершує повне рукостискання. Якщо отримано SYN-ACK → порт відкритий; RST → порт закритий. Логується цільовою системою.
  • SYN scan (-sS) — надсилає SYN, отримує SYN-ACK (відкритий) або RST (закритий), після чого одразу надсилає RST для розриву — ніколи не завершує рукостискання. Називається «напіввідкритий» або «stealth» scan.

Прапорці TCP

Заголовок TCP містить 6 основних прапорців, кожен з яких використовується у різних типах сканування:

Прапорець Функція Роль у скануванні
SYN Ініціалізація з'єднання SYN scan (-sS), Connect scan (-sT)
ACK Підтвердження отримання ACK scan (-sA) — маппінг фаєрволів
FIN Завершення з'єднання FIN scan (-sF)
RST Скидання з'єднання Індикатор закритого порту у відповіді
PSH Негайна доставка даних Xmas scan (FIN+PSH+URG)
URG Пріоритетна обробка Xmas scan (-sX)

Логіка за RFC 793: якщо закритий порт отримує пакет без прапорця RST, він відповідає RST. Якщо відкритий порт отримує пакет FIN/NULL/Xmas (без SYN, RST, ACK), він мовчки його відкидає. На цьому базуються FIN, Null та Xmas скани. Однак Windows, Cisco та BSDI порушують RFC 793 і надсилають RST незалежно від стану порту, що робить ці скани ненадійними проти цих ОС.

Протокол UDP

UDP (User Datagram Protocol) — протокол без встановлення з'єднання. Це створює фундаментальні проблеми для сканування:

  • Відсутність відповіді від відкритого UDP-порту — це нормальна поведінка (сервіс просто не відповідає на неочікувані дані)
  • ICMP Port Unreachable (Type 3, Code 3) — єдиний надійний індикатор закритого порту
  • Rate limiting: Linux обмежує ICMP unreachable до ~1/сек, тому повне сканування 65535 портів займає 18+ годин
  • Результат «немає відповіді» = open|filtered — неоднозначний (може бути відкритий або заблокований фаєрволом)
  • Протокольно-специфічні payload'и підвищують точність — база Nmap nmap-service-probes містить UDP-payload'и для DNS, SNMP, DHCP тощо

4.3 Типи сканування портів

TCP Connect Scan (-sT)

Використовує системний виклик connect() для повного TCP-рукостискання:

  • Відкритий порт: SYN → SYN-ACK → ACK (з'єднання встановлено, потім закрито)
  • Закритий порт: SYN → RST
  • Filtered: немає відповіді або ICMP unreachable

Переваги: не потребує root/admin привілеїв; працює на всіх платформах. Недоліки: найповільніший TCP-скан; повністю логується; легко виявляється IDS.

nmap -sT 192.168.1.100

SYN Scan / Stealth Scan (-sS)

Дефолтний тип сканування при запуску від root/admin. Надсилає SYN, аналізує відповідь, одразу надсилає RST — ніколи не завершує рукостискання:

  • Відкритий порт: SYN → SYN-ACK → RST (від сканера)
  • Закритий порт: SYN → RST (від цілі)
  • Filtered: немає відповіді після ретрансмісій, або ICMP Type 3

Переваги: швидкий (тисячі портів/сек); відносно стелсовий; розрізняє open/closed/filtered. Недоліки: потребує raw packet привілеїв; сучасні IDS легко виявляють.

nmap -sS 192.168.1.100

UDP Scan (-sU)

Надсилає UDP-пакети (порожні або з протокольно-специфічними payload'ами):

  • Open: отримано UDP-відповідь
  • Closed: ICMP Port Unreachable (Type 3, Code 3)
  • Filtered: інші ICMP unreachable (Codes 1, 2, 9, 10, 13)
  • Open|Filtered: немає відповіді (неоднозначно)

Головна проблема: rate-limited ICMP відповіді роблять повне сканування надзвичайно повільним. Рекомендація: комбінувати з -sV і сканувати конкретні порти.

nmap -sU -p 53,111,161,500 192.168.1.100

FIN Scan (-sF)

Надсилає TCP-пакет лише з прапорцем FIN. За RFC 793: закритий порт надсилає RST, відкритий мовчки відкидає пакет.

  • Open|Filtered: немає відповіді
  • Closed: отримано RST

Перевага: може обходити нестатичні (stateless) фаєрволи. Обмеження: не працює на Windows (надсилає RST незалежно від стану).

Xmas Scan (-sX)

Встановлює прапорці FIN + PSH + URG — «загоряється як різдвяна ялинка». Та ж логіка що й FIN scan: RST = закритий, тиша = open|filtered. Незвична комбінація прапорців може збити з пантелику прості фільтри.

Null Scan (-sN)

Надсилає TCP-пакет з нульовими прапорцями (жодний не встановлений). Мінімальний пакет. Та ж RFC 793 логіка, ті ж обмеження на Windows.

ACK Scan (-sA)

Надсилає пакет лише з прапорцем ACK. Ніколи не визначає відкриті порти — цей скан маппить правила фаєрвола:

  • Unfiltered: отримано RST (порт доступний, але open/closed невідомо)
  • Filtered: немає відповіді або ICMP unreachable (фаєрвол блокує)

Використання: визначити, чи фаєрвол є stateful або stateless; які порти проходять через фаєрвол.

Idle / Zombie Scan (-sI)

Найстелсовіший тип сканування — жоден пакет від вашої реальної IP-адреси не досягає цілі. Використовує «зомбі» — хост із передбачуваним інкрементальним IP ID.

Механізм (3 кроки на кожен порт):

  1. Probe zombie: надіслати SYN-ACK до зомбі, отримати RST. Записати поточний IP ID (наприклад, IPID=31337)
  2. Forge SYN: надіслати SYN до цільового порту зі spoofed source IP = zombie. Якщо порт відкритий: ціль → SYN-ACK → zombie → RST (IP ID +1). Якщо порт закритий: ціль → RST → zombie ігнорує
  3. Probe zombie знову: якщо IP ID збільшився на 2 = порт відкритий. Якщо на 1 = закритий/filtered
nmap -sI zombie.example.com 192.168.1.100

4.4 Nmap: головний інструмент сканування

Nmap (Network Mapper) — створений Гордоном «Fyodor» Ліоном у 1997 році. Де-факто стандарт для мережевого сканування, використовується пентестерами, адміністраторами та дослідниками безпеки по всьому світу. Відкритий код, активно підтримується.

nmap -sS --source-port 53 -T4 192.168.1.100

4.5 Визначення сервісів та операційних систем

Детекція версій сервісів (-sV)

Після виявлення відкритих портів наступний крок — визначити, що саме працює: назва додатку, версія, конфігурація. Nmap використовує складний алгоритм:

  1. NULL probe — порожнє з'єднання. Багато сервісів спонтанно надсилають банери (SSH, FTP, SMTP)
  2. Якщо збігу немає — надсилає проби з бази nmap-service-probes у порядку ймовірності
  3. Порівнює відповіді з regex-шаблонами для ідентифікації сервісу, додатку, версії, hostname, типу пристрою
Параметр Рівень Опис
--version-light2Швидко, мало проб — для масового сканування
(дефолт)7Збалансований — покриває більшість сервісів
--version-all9Максимум проб — повільно, але найточніше
nmap -sV --version-intensity 5 192.168.1.100

Фінгерпринтинг ОС (-O)

TCP/IP стек кожної ОС має унікальні характеристики — як відбитки пальців. Nmap надсилає серію спеціально сконструйованих пакетів та аналізує відповіді:

Проби фінгерпринтингу:

  • SEQ (6 SYN-пакетів) до відкритого порту з інтервалом 100мс — аналіз ISN, IP ID, TCP timestamps
  • 2 ICMP Echo з різними TOS, кодами та розмірами payload
  • 6 TCP-проб (T2-T7) з різними комбінаціями прапорців до відкритих та закритих портів
  • ECN probe — SYN з прапорцями CWR+ECE для тестування підтримки ECN
  • UDP probe (U1) — до закритого порту; аналіз ICMP unreachable відповіді

# Netcat — універсальний інструмент
nc -nv 192.168.1.100 22         # SSH банер
nc -nv 192.168.1.100 21         # FTP банер
nc -nv 192.168.1.100 80         # HTTP (потім: GET / HTTP/1.0)

# Telnet
telnet 192.168.1.100 25         # SMTP банер

# curl (HTTP заголовки)
curl -I http://192.168.1.100

# Nmap
nmap -sV --script banner -p 21,22,25,80 192.168.1.100

Увага: банери можуть бути підробленими! Адміністратори часто змінюють банери для дезінформації. Завжди перевіряйте кількома методами.

4.6 Nmap Scripting Engine (NSE)

4.7 Enumeration: збір детальної інформації

Enumeration (перелічення) — це процес глибокого збору інформації з виявлених сервісів. На відміну від сканування, яке визначає «що відкрито», enumeration відповідає на питання «що саме там працює і як це можна використати». Кожен відкритий сервіс — потенційний вектор атаки.

SMB Enumeration (порти 139, 445)

Server Message Block — протокол файлового та принтерного обміну у Windows-мережах. Один із найважливіших векторів атаки.

# enum4linux — комплексний інструмент (обгортка rpcclient + smbclient + nmblookup)
enum4linux -a 192.168.1.100              # Повне перелічення
enum4linux -U 192.168.1.100              # Користувачі
enum4linux -S 192.168.1.100              # Шари (shares)
enum4linux -P 192.168.1.100              # Політика паролів

# smbclient — прямий доступ до SMB
smbclient -L //192.168.1.100 -N          # Список шар (null session)
smbclient //192.168.1.100/share -U user  # Підключення до шари

# Nmap NSE
nmap -p445 --script smb-enum-shares,smb-enum-users 192.168.1.100
nmap -p445 --script smb-vuln-ms17-010 192.168.1.100
nmap -p445 --script smb-os-discovery 192.168.1.100

# rpcclient — RPC-перелічення
rpcclient -U "" -N 192.168.1.100        # Null session
# > enumdomusers                         # Користувачі домену
# > enumdomgroups                        # Групи домену

Null Session — неавтентифіковане з'єднання до SMB, яке дозволяє отримати NetBIOS-імена, шари, користувачів та групи без пароля.

SNMP Enumeration (порт 161 UDP)

Simple Network Management Protocol — часто залишається з дефолтними community strings (public для читання, private для запису).

# snmpwalk — рекурсивний обхід MIB-дерева
snmpwalk -v 2c -c public 192.168.1.100          # Повний обхід
snmpwalk -v 2c -c public 192.168.1.100 system   # Тільки системна інформація

# Конкретні OID для цінної інформації
snmpwalk -v 2c -c public target 1.3.6.1.2.1.25.4.2.1.2    # Запущені процеси
snmpwalk -v 2c -c public target 1.3.6.1.2.1.25.6.3.1.2    # Встановлене ПЗ
snmpwalk -v 2c -c public target 1.3.6.1.2.1.2.2.1.2       # Мережеві інтерфейси

# onesixtyone — брутфорс community strings
onesixtyone -c community_strings.txt 192.168.1.100

# Nmap
nmap -sU -p161 --script snmp-brute,snmp-info 192.168.1.100
OID Інформація
1.3.6.1.2.1.1.1.0Опис системи
1.3.6.1.2.1.1.3.0Uptime системи
1.3.6.1.2.1.1.5.0Ім'я системи
1.3.6.1.2.1.25.4.2.1.2Запущені процеси
1.3.6.1.2.1.25.6.3.1.2Встановлене ПЗ
1.3.6.1.2.1.6.13.1.3Відкриті TCP-порти

SNMPv1/v2c надсилають community strings у cleartext. SNMPv3 додає шифрування та автентифікацію.

DNS Enumeration (порт 53)

# Zone transfer (AXFR) — повна копія зони DNS
dig axfr example.com @ns1.example.com
host -t axfr example.com ns1.example.com

# Запити конкретних записів
dig example.com ANY              # Всі записи
dig example.com MX               # Поштові сервери
dig example.com NS               # Name-сервери
dig -x 192.168.1.100             # Зворотний DNS

# Автоматизовані інструменти
dnsrecon -d example.com -t axfr   # Zone transfer
dnsrecon -d example.com -t brt    # Брутфорс субдоменів
fierce --domain example.com       # Словникова атака + zone transfer

# Nmap
nmap -p53 --script dns-zone-transfer --script-args dns-zone-transfer.domain=example.com ns1.example.com
nmap -p53 --script dns-brute example.com

Вразливість zone transfer: AXFR не має вбудованої автентифікації — будь-який клієнт може запросити повну копію зонного файлу. Правильно налаштовані DNS-сервери обмежують AXFR лише авторизованим вторинним серверам.

LDAP Enumeration (порти 389, 636)

# Анонімний LDAP-запит
ldapsearch -x -H ldap://192.168.1.100 -b "dc=example,dc=com" "(objectClass=*)"

# Перелічення користувачів
ldapsearch -x -H ldap://192.168.1.100 -b "dc=example,dc=com" "(objectClass=user)" sAMAccountName mail

# Пошук Domain Admins
ldapsearch -x -H ldap://192.168.1.100 -b "dc=example,dc=com" "(&(objectClass=group)(cn=Domain Admins))" member

# Service Principal Names (для Kerberoasting)
ldapsearch -x -H ldap://192.168.1.100 -b "dc=example,dc=com" "(servicePrincipalName=*)" sAMAccountName servicePrincipalName

# Nmap
nmap -p389 --script ldap-rootdse,ldap-search 192.168.1.100

NFS Enumeration (порти 111, 2049)

# Список експортованих шар
showmount -e 192.168.1.100

# RPC-сервіси
rpcinfo -p 192.168.1.100

# Монтування NFS-шари
mount -t nfs 192.168.1.100:/share /mnt/nfs

# Nmap
nmap -p111,2049 --script nfs-ls,nfs-statfs,nfs-showmount 192.168.1.100

Ключова вразливість: опція no_root_squash у /etc/exports дозволяє root на клієнті бути root на сервері. Також можливе UID-підроблення у NFSv3 та нижче.

SMTP Enumeration (порт 25)

# Ручна перевірка через telnet/netcat
telnet 192.168.1.100 25
  HELO test
  VRFY admin           # 252 = існує, 550 = невідомий
  EXPN admins          # Розгорнути список розсилки
  RCPT TO:admin@example.com   # 250 = валідний, 550 = невалідний

# Автоматизований інструмент
smtp-user-enum -M VRFY -U users.txt -t 192.168.1.100
smtp-user-enum -M RCPT -U users.txt -t 192.168.1.100

# Nmap
nmap -p25 --script smtp-enum-users,smtp-commands,smtp-open-relay 192.168.1.100

RCPT TO — найбільш корисний метод, бо VRFY та EXPN часто вимкнені, а RCPT TO не можна вимкнути без порушення доставки пошти.

NetBIOS Enumeration (порти 137-139)

# nbtscan — масове сканування NetBIOS імен
nbtscan 192.168.1.0/24          # Скан підмережі
nbtscan -r 192.168.1.100        # Один хост з деталями

# Nmap
nmap -sU -p137 --script nbstat 192.168.1.100

Веб-сервер Enumeration

# Nikto — сканер веб-вразливостей (6700+ перевірок)
nikto -h http://192.168.1.100
nikto -h https://192.168.1.100 -ssl

# Gobuster — брутфорс директорій та файлів

4.8 Обхід захисту та методологія сканування

Як IDS/IPS виявляють сканування

Тип скану Сигнатура IDS
SYN scanВеликий обсяг SYN без завершення рукостискання; SYN → RST
Connect scanКороткоживучі TCP-сесії, відкриті та одразу закриті
FIN/NULL/XmasПакети з незвичними комбінаціями прапорців
ACK scanНесанкціоновані ACK до невстановлених з'єднань
UDP scanВеликий обсяг UDP + шквал ICMP unreachable
Idle scanНайважче виявити — IDS бачить трафік від зомбі, не від сканера

Snort за замовчуванням алертує при 15+ портів/сек від одного джерела. Повільні скани нижче цього порогу проходять непоміченими.

Техніки обходу

Фрагментація — розбиває TCP-заголовок на кілька IP-фрагментів. Деякі фаєрволи не вміють їх збирати:

nmap -f 192.168.1.100                    # 8-байтні фрагменти
nmap -f -f 192.168.1.100                 # 16-байтні
nmap --mtu 24 192.168.1.100              # Кастомний MTU (кратний 8)

Декої (Decoys) — ціль бачить SYN від багатьох IP і не може визначити реальний сканер:

nmap -D 10.0.0.1,10.0.0.2,ME,10.0.0.3 192.168.1.100
nmap -D RND:10 192.168.1.100             # 10 випадкових IP

Тайминг — уповільнення для обходу порогових значень IDS:

nmap -T0 192.168.1.100                   # 5 хв між пробами
nmap --scan-delay 5s 192.168.1.100       # 5-секундна затримка
nmap --max-rate 1 192.168.1.100          # 1 пакет/сек

Маскування джерела — деякі фаєрволи довіряють трафіку з DNS (53) або HTTP (80):

nmap --source-port 53 192.168.1.100      # Маскування під DNS
nmap -g 80 192.168.1.100                 # Маскування під HTTP

Padding та MAC-спуфінг:

nmap --data-length 25 192.168.1.100      # Рандомний padding
nmap --spoof-mac 0 192.168.1.100         # Випадковий MAC (тільки LAN)
nmap --spoof-mac Apple 192.168.1.100     # Рандомний Apple MAC

Bad Checksum — справжні TCP/IP стеки відкидають пакети з невірною контрольною сумою. Фаєрволи/IDS, що відповідають на такі пакети, виявляють свою присутність:

nmap --badsum 192.168.1.100

Комбінований стелс-скан:

nmap -sS -T1 -f --data-length 24 -D RND:5 --source-port 53 --spoof-mac 0 -Pn 192.168.1.100

Альтернативні інструменти сканування

Оптимальний workflow: Masscan/RustScan для швидкого виявлення відкритих портів → Nmap для детального аналізу:

# Masscan → Nmap
masscan 192.168.1.0/24 -p- --rate 10000 -oG discovered.gnmap
nmap -sV -sC -p <порти> <хости>

# RustScan → Nmap (автоматично)
rustscan -a 192.168.1.100 -- -sV -sC

# hping3 — крафтинг пакетів
hping3 -S 192.168.1.100 -p 80 -c 1         # Одиночний SYN
hping3 -S 192.168.1.100 --scan 1-1024       # Скан діапазону

Методологія сканування (PTES)

Рекомендована послідовність підфаз сканування — від широкого до вузького:

  1. Network Sweep — знайти живі хости: nmap -sn 192.168.1.0/24
  2. Port Scanning — знайти відкриті порти: nmap -sS -p- -T4 target
  3. Service Enumeration — визначити версії: nmap -sV -sC target
  4. OS Fingerprinting — визначити ОС: nmap -O target
  5. Vulnerability Assessment — перевірити CVE: nmap --script vuln target
  6. Deep Enumeration — протокольно-специфічні інструменти: enum4linux, snmpwalk, gobuster тощо

Документування та звітування

  • Завжди зберігайте результати — використовуйте -oA для збереження у всіх форматах
  • Часові мітки — фіксуйте час кожного сканування
  • Скріншоти — документуйте ключові знахідки
  • Структура звіту: хост → відкриті порти → сервіси → вразливості → рекомендації
  • Класифікація ризиків: Critical / High / Medium / Low / Informational
