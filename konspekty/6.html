Брутфорс та атаки на паролі

2 год Нова

6.1 Вступ до атак на паролі

Паролі залишаються основним механізмом автентифікації у переважній більшості інформаційних систем. Незважаючи на розвиток біометрії, токенів та безпарольної автентифікації, паролі використовуються для захисту облікових записів у 80%+ сервісів. Саме тому атаки на паролі є одним із найпоширеніших та найефективніших векторів компрометації.

За даними звіту Verizon Data Breach Investigations Report (DBIR) 2024, скомпрометовані облікові дані (stolen credentials) були задіяні у 81% зламів, пов'язаних із хакерськими атаками. Це робить паролі вразливістю номер один у корпоративній безпеці.

Класифікація атак на паролі

Атаки на паролі можна класифікувати за кількома критеріями:

Критерій Тип Опис
За вектором Онлайн-атака Спроби автентифікації через мережевий сервіс (SSH, HTTP, FTP). Обмежена швидкістю відповіді сервера та механізмами блокування
Офлайн-атака Зламування хешів паролів, отриманих із бази даних або файлової системи. Обмежена лише обчислювальними ресурсами атакуючого
За методом Brute-force (повний перебір) Перебір усіх можливих комбінацій символів. Гарантовано знаходить пароль, але потребує значних ресурсів
Dictionary (словникова) Перебір слів із підготовленого словника. Швидка, але знаходить лише паролі, присутні у словнику
Hybrid (гібридна) Комбінація словника з правилами мутації: додавання цифр, зміна регістру, leet-speak
Rule-based (на основі правил) Застосування трансформаційних правил до базових слів (Hashcat/JtR rules)
Rainbow Tables Використання попередньо обчислених таблиць хеш-пароль. Time-memory tradeoff
Credential Stuffing Використання пар email:password із витоків даних проти інших сервісів

Credential Stuffing vs Password Spraying

Два найпоширеніші типи мережевих атак на паролі принципово відрізняються підходом:

Параметр Credential Stuffing Password Spraying
Підхід Багато паролів для кожного акаунту Один пароль для багатьох акаунтів
Джерело Витоки даних (breaches) Загальні/типові паролі
Ціль Повторне використання паролів Обхід політик блокування
Детальніше Розділ 6.7 Розділ 6.7

Стандарт NIST SP 800-63B

NIST SP 800-63B (Digital Identity Guidelines: Authentication and Lifecycle Management) — основний стандарт для вимог до автентифікації, оновлений у 2024 році. Ключові рекомендації:

  • Мінімальна довжина пароля — 8 символів, рекомендована — 12+
  • Не вимагати обов'язкової зміни пароля через фіксований період (якщо немає ознак компрометації)
  • Не вимагати обов'язкового поєднання великих літер, цифр та спецсимволів (composition rules)
  • Перевіряти паролі проти списків скомпрометованих (breach lists)
  • Дозволяти всі друковані символи, включаючи пробіли
  • Обов'язково використовувати MFA для чутливих систем

Статистика паролів

  • Понад 10 мільярдів облікових записів скомпрометовано у відомих витоках даних (Have I Been Pwned, 2024)
  • 65% користувачів повторно використовують паролі на різних сервісах (Google Security Survey, 2023)
  • Середній користувач має 100+ облікових записів, але використовує лише 5-7 унікальних паролів
  • Середній час зламу 8-символьного пароля (a-z, GPU RTX 4090): менше 1 хвилини для MD5

Правові аспекти

Атаки на паролі, як і будь-які інші методи пентесту, є законними лише за наявності письмової авторизації. Необхідні документи:

  • Rules of Engagement (RoE) — чітко визначений scope: які системи, акаунти та сервіси дозволено тестувати
  • Обмеження інтенсивності — максимальна кількість спроб, часові вікна, щоб не спричинити DoS або масове блокування облікових записів
  • Кримінальний кодекс України, ст. 361 — несанкціоноване втручання в роботу комп'ютерних систем (до 6 років ув'язнення)
  • CFAA (Computer Fraud and Abuse Act, США) — несанкціонований доступ до комп'ютерних систем

6.2 Механізми автентифікації та зберігання паролів

Щоб ефективно атакувати паролі, пентестер повинен розуміти, як саме системи зберігають та перевіряють паролі. Сучасні системи ніколи не зберігають паролі у відкритому вигляді (plaintext) — замість цього використовуються хеш-функції.

Як працює хешування

Хеш-функція — це одностороння математична функція, що перетворює вхідні дані довільної довжини у вихідний рядок фіксованої довжини (хеш, дайджест). Ключові властивості:

  • Односторонність — неможливо відновити оригінальний пароль із хешу (за розумний час)
  • Детермінованість — однакові вхідні дані завжди дають однаковий хеш
  • Фіксована довжина — незалежно від довжини вхідних даних, хеш має фіксований розмір
  • Лавинний ефект — мінімальна зміна вхідних даних кардинально змінює хеш
  • Стійкість до колізій — практично неможливо знайти два різні входи з однаковим хешем
# Приклад хешування SHA-256
echo -n "password"  | sha256sum
5e884898da28047151d0e56f8dc6292773603d0d6aabbdd62a11ef721d1542d8

echo -n "password1" | sha256sum
0b14d501a594442a01c6859541bcb3e8164d183d32937b851835442f69d5c94e
# Повністю різний хеш при зміні лише одного символу!

Порівняння хеш-функцій

Алгоритм Розмір (біт) Статус Призначення Швидкість (RTX 4090)
MD5 128 Зламаний (колізії з 2004) Контрольні суми, legacy-системи ~164 GH/s
SHA-1 160 Зламаний (SHAttered, 2017) Legacy, Git (переходить на SHA-256) ~24 GH/s
SHA-256 256 Безпечний Цифрові підписи, TLS, Bitcoin ~22 GH/s
SHA-512 512 Безпечний Linux /etc/shadow ($6$) ~3.5 GH/s
bcrypt 184 Рекомендований Зберігання паролів (cost factor) ~184 KH/s
Argon2id Конфігуроване Найкращий (PHC 2015) Зберігання паролів (memory-hard) ~1000 H/s

Зверніть увагу на різницю у швидкості: MD5 обчислюється в 164 мільярди разів на секунду, тоді як Argon2id — лише приблизно 1000 разів. Це означає, що bcrypt/Argon2id спеціально спроєктовані бути повільними для захисту від брутфорсу.

Сіль (Salt)

Сіль — це випадкові дані, що додаються до пароля перед хешуванням. Кожен користувач має унікальну сіль.

# Без солі: однакові паролі = однакові хеші
hash("password") = 5e884898da2804...
hash("password") = 5e884898da2804...  # Ідентичний!

# З сіллю: однакові паролі = різні хеші
hash("aB9x" + "password") = 7c6a180b36896a...
hash("kM3p" + "password") = 2b6d36f83c28e1...  # Різні!

Переваги використання солі:

  • Захист від rainbow tables — для кожної солі потрібна окрема таблиця
  • Захист від порівняння хешів — два однакові паролі матимуть різні хеші
  • Сповільнення масового зламу — кожен хеш потрібно ламати окремо

Key Stretching (розтягування ключа)

Key stretching — це техніка багаторазового застосування хеш-функції для штучного сповільнення обчислення:

  • PBKDF2 — Password-Based Key Derivation Function 2. Рекомендовано 600,000+ ітерацій для SHA-256 (OWASP 2024)
  • bcrypt — використовує cost factor (log2 кількості ітерацій). Cost 12 = 2^12 = 4096 ітерацій. Рекомендовано cost ≥ 12
  • scrypt — memory-hard функція: потребує значних обсягів оперативної пам'яті, ускладнюючи GPU-атаки
  • Argon2id — переможець Password Hashing Competition (PHC) 2015. Поєднує стійкість до GPU (memory-hard) та side-channel атак. Параметри: пам'ять, ітерації, паралелізм

Pepper (перець)

Pepper — це секретний ключ на стороні сервера, що додається до пароля перед хешуванням. На відміну від солі, pepper не зберігається разом із хешем — він зберігається окремо (наприклад, у змінних середовища або HSM). Навіть якщо база даних з хешами та солями скомпрометована, без pepper'у атакуючий не зможе зламати паролі.

Linux: /etc/shadow

В Linux паролі зберігаються у файлі /etc/shadow, доступному лише root. Формат запису:

username:$id$salt$hash:lastchanged:min:max:warn:inactive:expire

# Приклад:
john:$6$xYz1aBcD$kL9m2nO3pQ4rS5tU6vW7xY8zA9bC0dE1fG2hI3jK4l:19500:0:99999:7:::

# Пояснення:
# $6$        — алгоритм (SHA-512)
# xYz1aBcD   — сіль
# kL9m2n...  — хеш
# 19500      — дні від 1 січня 1970 до останньої зміни

Ідентифікатори алгоритмів у /etc/shadow:

ID Алгоритм Статус
$1$MD5Застарілий, небезпечний
$5$SHA-256Прийнятний
$6$SHA-512Стандарт (більшість дистрибутивів)
$2b$bcryptРекомендований
$y$yescryptСучасний (Debian 11+, Fedora 35+)
# Корисні команди Linux
sudo cat /etc/shadow                    # Перегляд хешів
sudo unshadow /etc/passwd /etc/shadow   # Об'єднання для John the Ripper
sudo chpasswd <<< "user:newpassword"    # Зміна пароля

Windows: зберігання паролів

Windows використовує кілька механізмів зберігання паролів:

SAM (Security Account Manager) — база даних локальних облікових записів. Зберігається у C:\Windows\System32\config\SAM. Файл заблокований для читання під час роботи системи (процес lsass.exe тримає ексклюзивний замок).

LM Hash (LAN Manager) — застарілий алгоритм, вимкнений за замовчуванням з Windows Vista:

  • Базується на DES-шифруванні
  • Конвертує пароль у верхній регістр (case-insensitive)
  • Розбиває пароль на два 7-символьні блоки, кожен хешується окремо
  • Максимальна довжина — 14 символів
  • Вкрай слабкий: будь-який LM hash зламується за секунди

NTLM Hash (NT LAN Manager) — основний алгоритм Windows:

  • Формула: MD4(UTF-16-LE(password))
  • Не використовує сіль! — це критична слабкість
  • Однакові паролі дають однакові NTLM хеші на всіх Windows-системах
  • Швидкість зламу: RTX 4090 — ~300 GH/s (навіть швидше за MD5 через простоту MD4)
  • Використовується для автентифікації у мережах Windows (NTLMv1/v2, Kerberos)

NTDS.dit — база даних Active Directory, що містить хеші паролів усіх доменних користувачів. Знаходиться на контролері домену: C:\Windows\NTDS\ntds.dit.

6.3 Офлайн-атаки: John the Ripper та Hashcat

Офлайн-атаки — це зламування хешів паролів без взаємодії з цільовою системою. Атакуючий отримує хеші (через SQL injection, дамп бази, доступ до /etc/shadow або SAM) і зламує їх локально на своєму обладнанні. Швидкість обмежена лише обчислювальними ресурсами.

John the Ripper (JtR)

John the Ripper — один із найстаріших та найвідоміших інструментів для зламування паролів. Створений Solar Designer у 1996 році. Версія Jumbo (community-enhanced) підтримує понад 300 форматів хешів.

Режими роботи JtR

Режим Опис Команда
Single Crack Мутації на основі імені користувача та поля GECOS (ім'я, прізвище). Найшвидший для перших спроб john --single hashes.txt
Wordlist Перебір слів із файлу-словника. Може застосовувати правила мутації john --wordlist=rockyou.txt hashes.txt
Incremental Повний перебір усіх комбінацій за заданим набором символів john --incremental=Alnum hashes.txt
External Користувацький режим з C-подібними модулями john --external=Filter hashes.txt

Основні команди JtR

# Базовий запуск (автовизначення формату та режимів)
john hashes.txt

# Словникова атака
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt

# Словникова атака з правилами мутації
john --wordlist=rockyou.txt --rules=best64 hashes.txt

# Brute-force (incremental) тільки з маленькими латинськими
john --incremental=Lower hashes.txt

# Brute-force тільки з цифрами
john --incremental=Digits hashes.txt

# Вказати формат хешу
john --format=raw-md5 hashes.txt
john --format=raw-sha256 hashes.txt
john --format=NT hashes.txt

# Показати зламані паролі
john --show hashes.txt

# Показати стан (під час роботи натиснути Enter)
john --status

# Відновити перервану сесію
john --restore

Hashcat

Hashcat — найшвидший у світі інструмент для зламування паролів, що використовує GPU-прискорення (CUDA, OpenCL, Metal). Підтримує понад 350 алгоритмів хешування. Ключова перевага — масивний паралелізм GPU: одна відеокарта RTX 4090 обчислює мільярди хешів на секунду.

Режими атак Hashcat

Прапорець Режим Опис Приклад

-a 1 Combinator Комбінація двох словників: word1+word2 hashcat -a 1 -m 0 hashes.txt dict1.txt dict2.txt
-a 3 Brute-force / Mask Перебір за маскою (шаблоном) hashcat -a 3 -m 0 hashes.txt ?l?l?l?l?d?d

-a 7 Hybrid (mask+wordlist) Маска + слово: ?d?dpassword hashcat -a 7 -m 0 hashes.txt ?d?d dict.txt

Популярні набори правил (rule files):

  • best64.rule — 64 найефективніші правила, оптимальне співвідношення швидкість/результат. Зламує ~70% типових паролів у комбінації з rockyou.txt
  • d3ad0ne.rule — ~35,000 правил, агресивніший підхід
  • dive.rule — ~99,000 правил, глибокий перебір мутацій
  • OneRuleToRuleThemAll.rule — ~51,000 правил, оптимізований набір від NotSoSecure
# Словникова атака з правилами
hashcat -a 0 -m 1000 ntlm_hashes.txt rockyou.txt -r best64.rule

# Mask-атака: пароль = велика + 5 маленьких + 2 цифри
hashcat -a 3 -m 0 hashes.txt ?u?l?l?l?l?l?d?d

# Гібридна: словник + 4 цифри
hashcat -a 6 -m 0 hashes.txt rockyou.txt ?d?d?d?d

# Показати зламані
hashcat -m 0 hashes.txt --show

# Benchmark (тест швидкості)
hashcat -b -m 0     # MD5
hashcat -b -m 1000  # NTLM
hashcat -b -m 3200  # bcrypt

Практичний workflow зламування

  1. Ідентифікація формату: використати hashid або hash-identifier для визначення типу хешу
  2. Словникова атака: hashcat -a 0 -m MODE hashes.txt rockyou.txt
  3. Словник + правила: hashcat -a 0 -m MODE hashes.txt rockyou.txt -r best64.rule
  4. Гібридна: hashcat -a 6 -m MODE hashes.txt rockyou.txt ?d?d?d?d
  5. Mask-атака: hashcat -a 3 -m MODE hashes.txt ?u?l?l?l?l?l?d?d?s
  6. Повний перебір: hashcat -a 3 -m MODE hashes.txt ?a?a?a?a?a?a?a?a (8 символів)

Rainbow Tables

Rainbow Tables — попередньо обчислені таблиці відповідностей хеш-пароль, що реалізують принцип time-memory tradeoff: замість обчислення хешу для кожного пароля в реальному часі, атакуючий використовує готову таблицю для миттєвого пошуку.

  • RainbowCrack — основний інструмент: rtgen (генерація), rtsort (сортування), rcrack (зламування)
  • Розмір таблиць: MD5 (a-z, 1-8 символів) ≈ 460 GB
  • Повністю нейтралізуються сіллю — кожне значення солі потребує окремої таблиці
  • У сучасному пентесті rainbow tables переважно застарілі через швидкість GPU: зламування MD5 на RTX 4090 швидше, ніж пошук у таблиці
  • Досі корисні для LM Hash (Windows), де немає солі та обмежений набір символів

6.4 Онлайн-атаки: Hydra, Medusa, Ncrack

На відміну від офлайн-атак, онлайн-атаки (network brute-force) виконуються безпосередньо проти мережевих сервісів автентифікації. Атакуючий надсилає пари логін:пароль через мережевий протокол (SSH, FTP, HTTP тощо) та аналізує відповідь сервера. Швидкість обмежена мережевою затримкою, продуктивністю сервера та механізмами захисту (lockout, rate limiting).

THC-Hydra

THC-Hydra (автор: van Hauser / THC) — найпопулярніший інструмент для онлайн-брутфорсу. Підтримує понад 50 протоколів, включаючи SSH, FTP, RDP, VNC, HTTP-GET, HTTP-POST-FORM, SMB, MySQL, MSSQL, PostgreSQL, SMTP, POP3, IMAP, LDAP, Telnet, SIP, Redis, MongoDB та інші.

# SSH брутфорс (один логін, словник паролів)
hydra -l root -P /usr/share/wordlists/rockyou.txt \
  -t 4 -f 192.168.1.100 ssh

# FTP брутфорс (список логінів і паролів)
hydra -L users.txt -P passwords.txt \
  -t 8 -f 192.168.1.100 ftp

  -t 1 -w 5 192.168.1.100 rdp

  -t 4 192.168.1.100 smb

  -t 4 192.168.1.100 mysql

  192.168.1.100 http-get /admin/

  192.168.1.100 http-post-form \
  "/login:username=^USER^&password=^PASS^:F=Invalid credentials"

Синтаксис HTTP-form: "URL:ПАРАМЕТРИ:УМОВА_ПОМИЛКИ", де ^USER^ та ^PASS^ — маркери для підстановки, F= — текст, що з'являється при невдалому вході.

Medusa

Medusa — модульний інструмент для онлайн-брутфорсу. Стабільний для паралельного сканування кількох хостів одночасно.

# SSH брутфорс
medusa -h 192.168.1.100 -u root -P passwords.txt -M ssh -t 4

# FTP з файлом хостів
medusa -H hosts.txt -u admin -P passwords.txt -M ftp -T 4

# Combo-файл (host:user:pass)
medusa -C combo.txt -M ssh

Ncrack

Ncrack — розроблений командою Nmap. Інтегрується з результатами Nmap XML (-iX). Підтримує timing templates (-T 0-5).

# SSH брутфорс
ncrack -p ssh -U users.txt -P passwords.txt 192.168.1.100

# Використання результатів Nmap
ncrack -iX nmap_scan.xml -U users.txt -P passwords.txt

# Повільний режим (менше шансів на виявлення)
ncrack -T 2 -p ssh -U users.txt -P passwords.txt 192.168.1.100

Patator

Patator — модульний Python-інструмент з гнучкою системою фільтрації відповідей:

# SSH брутфорс
patator ssh_login host=192.168.1.100 user=root \
  password=FILE0 0=passwords.txt \
  -x ignore:mesg='Authentication failed.'

# FTP брутфорс
patator ftp_login host=192.168.1.100 user=admin \
  password=FILE0 0=passwords.txt \
  -x ignore:mesg='Login incorrect.'

# HTTP POST form
patator http_fuzz url=http://192.168.1.100/login method=POST \
  body='user=admin&pass=FILE0' 0=passwords.txt \
  -x ignore:fgrep='Invalid'

Burp Suite Intruder

Burp Suite Intruder — графічний інструмент для брутфорсу веб-форм. Workflow:

  1. Перехопити запит логіну через Proxy (Intercept)
  2. Надіслати запит у Intruder (Ctrl+I)
  3. Позначити позиції для підстановки (виділити значення та натиснути Add §)
  4. Обрати тип атаки та завантажити словник
  5. Запустити атаку та аналізувати відповіді за довжиною або статус-кодом

Виявлення та протидія онлайн-атакам

  • IDS/IPS алерти — Snort, Suricata виявляють масові спроби автентифікації
  • Account Lockout — блокування акаунту після N невдалих спроб (типово: 5 спроб, 30 хвилин блокування)
  • Fail2ban — моніторинг логів та автоматичне блокування IP через iptables/nftables
  • Rate Limiting — обмеження кількості запитів від одного IP за одиницю часу

  • Географічна фільтрація — блокування автентифікації з нетипових локацій

6.5 Словники та генерація wordlists

Ефективність словникової атаки повністю залежить від якості словника. Правильно підібраний wordlist може зламати 70-80% паролів за хвилини, тоді як повний brute-force тих самих паролів зайняв би роки.

Crunch — генератор wordlists, що створює усі можливі комбінації за заданим шаблоном та набором символів.

6.6 Атаки на Wi-Fi паролі

Wi-Fi мережі, захищені паролем, є поширеною ціллю для пентестерів. Зламування пароля Wi-Fi є офлайн-атакою: після захоплення handshake або PMKID атакуючий працює локально, без подальшого контакту з мережею.

WPA/WPA2 — огляд безпеки

  • WPA2-Personal (PSK) — Pre-Shared Key, один пароль для всіх користувачів
  • Хешування: PBKDF2 з 4096 ітераціями SHA-1 для генерації PMK (Pairwise Master Key) із PSK + SSID
  • Шифрування: CCMP/AES (WPA2), TKIP (WPA, застарілий)
  • PMK = PBKDF2(HMAC-SHA1, PSK, SSID, 4096, 256)

4-Way Handshake

Процес взаємної автентифікації між клієнтом (STA) та точкою доступу (AP):

  1. AP → STA: ANonce (випадкове число від AP)
  2. STA → AP: SNonce + MIC (клієнт обчислює PTK = f(PMK, ANonce, SNonce, MAC_AP, MAC_STA), надсилає SNonce та MIC для верифікації)
  3. AP → STA: GTK (груповий ключ, зашифрований PTK) + MIC
  4. STA → AP: ACK (підтвердження)

Для зламування достатньо захопити перші два повідомлення handshake. Далі атакуючий перебирає паролі локально, генеруючи PMK → PTK → MIC та порівнюючи MIC із захопленим.

Атака на WPA2: повний workflow

# Крок 1: Увімкнення режиму монітора
sudo airmon-ng start wlan0
# Інтерфейс стає wlan0mon

# Крок 2: Сканування мереж
sudo airodump-ng wlan0mon
# Записати: BSSID (MAC AP), CH (канал), ESSID (назва мережі)

# Крок 3: Захоплення handshake (фокус на конкретну мережу)
sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF \
  -w capture wlan0mon
# -c 6    — канал
# --bssid — MAC-адреса точки доступу
# -w      — ім'я файлу для збереження

# Крок 4: Деаутентифікація (у другому терміналі)
# Примусово відключити клієнта, щоб він перепідключився і ми захопили handshake
sudo aireplay-ng -0 5 -a AA:BB:CC:DD:EE:FF \
  -c 11:22:33:44:55:66 wlan0mon
# -0 5    — 5 деаутентифікаційних пакетів
# -a      — BSSID точки доступу
# -c      — MAC клієнта (необов'язково, без -c деаутентифікує всіх)

# Крок 5: Зламування (після захоплення handshake)
aircrack-ng -w /usr/share/wordlists/rockyou.txt capture-01.cap

# Або через Hashcat (значно швидше з GPU):
# Конвертація формату
hcxpcapngtool capture-01.cap -o hash.hc22000
# Зламування
hashcat -a 0 -m 22000 hash.hc22000 rockyou.txt

PMKID-атака (2018)

У серпні 2018 Jens Steube (автор Hashcat) виявив новий метод атаки на WPA/WPA2, що не потребує захоплення handshake і, відповідно, не потребує підключеного клієнта.

  • PMKID = HMAC-SHA1-128(PMK, "PMK Name" || MAC_AP || MAC_STA)
  • AP надсилає PMKID у першому EAPOL-фреймі при спробі підключення
  • Атакуючий просто ініціює підключення та отримує PMKID
  • Далі — стандартний офлайн-перебір із Hashcat (-m 22000)
# Захоплення PMKID
sudo hcxdumptool -i wlan0mon -o dump.pcapng \
  --enable_status=1 --filterlist_ap=AA:BB:CC:DD:EE:FF \
  --filtermode=2

# Конвертація
hcxpcapngtool dump.pcapng -o hash.hc22000

# Зламування
hashcat -a 0 -m 22000 hash.hc22000 rockyou.txt

WPS PIN-атака

WPS (Wi-Fi Protected Setup) — функція спрощеного підключення через 8-значний PIN. Критична вразливість: PIN перевіряється двома частинами (4+3 цифри + контрольна сума), що зменшує простір перебору з 10^8 до ~11,000 комбінацій.

# Сканування мереж з увімкненим WPS
wash -i wlan0mon

# Атака на WPS PIN
reaver -i wlan0mon -b AA:BB:CC:DD:EE:FF -vv
# Час: ~2-10 годин (якщо немає rate limiting)

# Bully — альтернатива Reaver
bully wlan0mon -b AA:BB:CC:DD:EE:FF -e "NetworkName" -c 6

Evil Twin / Fluxion

Evil Twin — створення підробної точки доступу, ідентичної легітимній. Процес:

  1. Створити копію цільової мережі (той самий SSID, MAC)
  2. Деаутентифікувати клієнтів від легітимної AP
  3. Клієнти підключаються до підробної AP
  4. Captive portal запитує «пароль Wi-Fi для оновлення»
  5. Fluxion перевіряє введений пароль проти захопленого handshake

Fluxion автоматизує весь процес Evil Twin атаки.

Wifite2

Wifite2 — автоматизований інструмент аудиту Wi-Fi. Автоматично виявляє мережі, захоплює handshake/PMKID, атакує WPS, та запускає зламування словником:

# Запуск (автоматичний режим)
sudo wifite

# Вказати конкретний словник
sudo wifite --dict /usr/share/wordlists/rockyou.txt

WPA3-SAE

WPA3 (2018) використовує SAE (Simultaneous Authentication of Equals) — протокол Dragonfly key exchange:

  • Захист від офлайн-атак — навіть із захопленим трафіком неможливо перебрати паролі офлайн
  • Forward Secrecy — компрометація ключа не розкриває минулий трафік
  • Dragonblood (2019) — вразливості CVE-2019-9494 та CVE-2019-9495, side-channel атаки на SAE. Виправлені у оновленнях
  • Transition mode — WPA3/WPA2 сумісність дозволяє downgrade-атаки: примусити клієнта підключитись через WPA2

Швидкість зламування WPA2

Пароль RTX 4090 (~2.5 MH/s)
8 символів (a-z)~23 години
8 символів (a-z, 0-9)~4 дні
8 символів (a-zA-Z0-9)~98 днів
10 символів (a-z)~6.5 років
12 символів (a-z)~4400 років

Захист Wi-Fi

  • Використовувати WPA3 (або WPA2-Enterprise/RADIUS для корпоративних мереж)
  • Вимкнути WPS — основний вектор атаки на побутові роутери
  • Довга парольна фраза: 12+ символів, краще випадково згенерована
  • Регулярне оновлення прошивки роутера
  • Моніторинг підключених пристроїв та rogue AP detection

6.7 Credential Stuffing та Password Spraying

Ці два типи атак експлуатують людський фактор — звички користувачів у створенні та управлінні паролями. На відміну від класичного брутфорсу, вони оптимізовані для уникнення механізмів захисту.

Credential Stuffing

Credential Stuffing — автоматизоване використання пар email:password з витоків даних для спроб автентифікації на інших сервісах. Ефективність базується на тому, що 65% користувачів повторно використовують паролі на різних сервісах.

  • Успішність: 0.1-2% від загальної кількості спроб. При мільйонах пар це тисячі скомпрометованих акаунтів
  • Масштаб: 193 мільярди спроб credential stuffing зафіксовано у 2024 році (Akamai State of the Internet)
  • Інструменти: SentryMBA, OpenBullet 2, Snipr, власні скрипти на Python/Go

Типова схема credential stuffing:

  1. Отримання бази витоків (darknet, Telegram-канали, публічні дампи)
  2. Очищення та дедуплікація: email:password пари
  3. Ротація проксі (residential proxies, SOCKS5, Tor) для обходу IP-блокування
  4. Антибот-обхід: ротація User-Agent, затримки між запитами, CAPTCHA-солвери
  5. Масовий перебір проти цільових сервісів
  6. Збір та монетизація скомпрометованих акаунтів

Password Spraying

Password Spraying — зворотний підхід: один пароль перебирається проти багатьох акаунтів. Це дозволяє обійти політики блокування облікових записів, оскільки кожен акаунт отримує лише 1-2 спроби.

  • Типові паролі для spraying: Spring2025!, Summer2025!, Welcome1, Password1!, Company123, Qwerty123!
  • Затримка: 30-60 хвилин між спробами (щоб уникнути lockout)
  • Ідеальна ціль: Active Directory з тисячами облікових записів

Інструменти для Password Spraying:

Інструмент Протоколи Команда
CrackMapExec / NetExec SMB, WinRM, LDAP, MSSQL, SSH nxc smb 10.10.10.0/24 -u users.txt -p 'Spring2025!' --continue-on-success
Spray (Greenwolf) SMB, OWA, Lync, CISCO spray.sh -smb 10.10.10.100 users.txt passwords.txt 1 35
Kerbrute Kerberos (AD) kerbrute passwordspray -d domain.local users.txt 'Spring2025!'
Ruler Exchange / Outlook ruler --domain domain.com brute --users users.txt --passwords pass.txt

Kerberos pre-auth spraying через Kerbrute є особливо ефективним: він швидший за SMB і генерує менше логів, оскільки невдалі спроби Kerberos не завжди логуються як failed login events (Event ID 4625).

Have I Been Pwned (HIBP)

Have I Been Pwned — проєкт Troy Hunt, що дозволяє перевірити, чи були ваші облікові дані скомпрометовані:

  • 13+ мільярдів скомпрометованих облікових записів з 800+ витоків
  • k-anonymity API — дозволяє перевіряти паролі без надсилання повного хешу (надсилаються лише перші 5 символів SHA-1)
  • Інтеграція: Firefox Monitor, 1Password, Bitwarden, Azure AD Password Protection
  • URL: haveibeenpwned.com
# Перевірка пароля через API (k-anonymity)
# SHA-1 хеш "password" = 5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8
# Надсилаємо перші 5 символів: 5BAA6
curl https://api.pwnedpasswords.com/range/5BAA6
# Відповідь містить хвости хешів та кількість витоків
# 1E4C9B93F3F0682250B6CF8331B7EE68FD8:10434788
# Знайдено 10,434,788 разів!

Реальні інциденти

Colonial Pipeline (2021)

  • Вектор: один скомпрометований VPN-обліковий запис (пароль із витоку)
  • Відсутність MFA на VPN-шлюзі
  • Наслідки: ransomware DarkSide, зупинка найбільшого нафтопроводу США, $4.4 млн викупу

Okta (2024)

  • Вектор: credential stuffing через residential proxies
  • Наслідки: компрометація клієнтських тенантів, крадіжка Okta session tokens

Microsoft / Midnight Blizzard (2024)

  • Вектор: password spraying на тестовий обліковий запис без MFA
  • Атакуючий: APT29 / Cozy Bear (російська розвідка)
  • Наслідки: доступ до корпоративних email, включаючи листування керівництва Microsoft

6.8 Захист від атак на паролі

Ефективний захист від атак на паролі потребує багаторівневого підходу: від вибору стійких алгоритмів хешування до впровадження безпарольної автентифікації. Жоден окремий захід не є достатнім — лише їх комбінація забезпечує надійний захист.

Multi-Factor Authentication (MFA)

MFA (багатофакторна автентифікація) — найефективніший захист від атак на паролі. За даними Microsoft (2023), MFA блокує 99.9% автоматизованих атак.

Три фактори автентифікації:

  • Knowledge (знання) — пароль, PIN, секретне питання
  • Possession (володіння) — телефон, апаратний ключ, смарт-карта
  • Inherence (властивість) — біометрія: відбиток пальця, обличчя, голос
  • Location (додатковий) — геолокація, IP-адреса, мережа

Типи MFA:

Тип Як працює Безпека
TOTP Генерація 6-цифрового коду кожні 30 секунд (Google Authenticator, Authy, Microsoft Authenticator) Висока. Вразливий до фішингу з real-time relay
Push notification Повідомлення на телефон: «Підтвердити вхід?» (Microsoft Authenticator, Duo) Висока. Вразливий до MFA Fatigue
SMS OTP Одноразовий код через SMS Низька. Вразливий до SIM-swap, SS7, перехоплення
FIDO2 / WebAuthn Апаратний ключ (YubiKey) або біометрія пристрою Найвища. Стійкий до фішингу (криптографічна прив'язка до домену)
Passkeys FIDO2 з синхронізацією між пристроями (iCloud, Google) Найвища. Замінює паролі повністю

Атаки на MFA

  • MFA Fatigue / Push Bombing — масове надсилання push-повідомлень, поки жертва не натисне «Approve» від втоми. Використовувалось у зламі Uber (2022) групою Lapsus$
  • SIM Swapping — перенесення номера телефону жертви на SIM-карту атакуючого через соціальну інженерію оператора зв'язку
  • Evilginx2 — reverse proxy для фішингу, що перехоплює session cookies та MFA-токени у реальному часі. Жертва проходить справжній процес логіну, але через проксі атакуючого
  • Real-time relay — ручне або автоматичне пересилання MFA-кодів у реальному часі

Account Lockout Policy

Типова конфігурація: 5 невдалих спроб → блокування на 30 хвилин. Проблема: зловмисник може навмисно блокувати акаунти (DoS). Рішення:

  • Smart Lockout (Azure AD) — блокує підозрілі IP, але пропускає легітимні. Використовує ML для розрізнення
  • Progressive delays — замість повного блокування, збільшувати затримку: 1с, 5с, 30с, 5хв
  • CAPTCHA після N спроб — рішення, що не блокує легітимних користувачів

Fail2ban

Fail2ban — інструмент моніторингу логів, що автоматично блокує IP-адреси з підозрілою активністю через iptables/nftables:

# Конфігурація /etc/fail2ban/jail.local
[sshd]
enabled  = true
port     = ssh
filter   = sshd
logpath  = /var/log/auth.log
maxretry = 5          # Максимум невдалих спроб
bantime  = 3600       # Час блокування (секунди) = 1 година
findtime = 600        # Вікно спостереження (секунди) = 10 хвилин
action   = iptables-multiport[name=sshd, port="ssh"]

# Статус
sudo fail2ban-client status sshd
# Status for the jail: sshd
# |- Filter
# |  |- Currently failed: 3
# |  |- Total failed:     147
# |  `- File list:        /var/log/auth.log
# `- Actions
#    |- Currently banned: 2
#    |- Total banned:     18
#    `- Banned IP list:   185.x.x.x 91.x.x.x

# Розблокувати IP
sudo fail2ban-client set sshd unbanip 185.x.x.x

# Підтримувані сервіси:
# SSH, Apache, Nginx, Postfix, vsftpd, ProFTPD, Dovecot та інші

Менеджери паролів

Менеджери паролів вирішують проблему повторного використання паролів, генеруючи унікальний складний пароль для кожного сервісу:

Менеджер Тип Особливості
Bitwarden Open-source, хмарний/self-hosted Безкоштовний план, аудит коду (Cure53), self-hosting
KeePass / KeePassXC Офлайн, open-source Локальний файл .kdbx, плагіни, повний контроль
1Password Комерційний, хмарний Travel Mode, Secret Key + Master Password, Watchtower
LastPass Комерційний, хмарний Зазнав витоків (2022): зашифровані сховища + метадані вкрадені

Passkeys (FIDO2 / WebAuthn)

Passkeys — нове покоління автентифікації, що повністю замінює паролі криптографічними ключами:

  • Принцип: публічний ключ зберігається на сервері, приватний — на пристрої користувача (TPM, Secure Enclave)
  • Phishing-resistant: криптографічно прив'язані до домену. Passkey для google.com не спрацює на g00gle.com
  • Розблокування: біометрія (Touch ID, Face ID) або PIN на пристрої
  • Синхронізація: iCloud Keychain (Apple), Google Password Manager (Android/Chrome)
  • Стандарт: WebAuthn (W3C) + CTAP2 (FIDO Alliance)

Впровадження passkeys:

  • Google — 400+ мільйонів акаунтів з passkeys (2024)
  • Microsoft — passkeys за замовчуванням для нових акаунтів
  • Apple — інтеграція в iOS/macOS через iCloud Keychain
  • GitHub — підтримка passkeys для всіх акаунтів

Zero Trust автентифікація

Принцип Zero Trust — «ніколи не довіряй, завжди перевіряй» — застосовується до автентифікації:

  • Continuous verification — перевірка не лише при вході, але постійно протягом сесії
  • Context-aware access — враховувати геолокацію, пристрій, час, мережу
  • Least privilege — мінімально необхідні привілеї для кожної сесії
  • Micro-segmentation — кожен ресурс потребує окремої автентифікації
  • Assume breach — проєктувати системи, виходячи з того, що периметр вже скомпрометований
